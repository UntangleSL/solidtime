## Phase Goal

**As a** team member tracking time, **I want to** turn one or several meeting suggestions into time entries on a project in a single action, **so that** logging meeting time takes one click instead of re-typing it from Outlook.

<objective>
Assigning several meetings at once: a floating bar while meetings are selected, the batch form in a popover over it, one request for all selected meetings, a result row per meeting with the reason for each failure, and a retry of only the failed ones.

Purpose: ASGN-04 and roadmap criterion 2 (D-07, D-08, D-16).
Output: OutlookSelectionBar, batch mode of OutlookConvertForm, OutlookAssignResults, the bar mount in Calendar.vue (one import and one element, ledgered by 04-07), Vitest coverage.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Outlook meeting text -> batch rows | Subjects from other people's calendars are rendered in the list |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-20 | Tampering (XSS) | OutlookConvertForm batch rows, OutlookAssignResults | high | mitigate | Text interpolation only; server failure messages are rendered as text |
| T-04-21 | Denial of service | oversized batch | low | mitigate | Selection holds only rendered meetings of one week; the server caps at 50 ids and throttles; a 422 or 429 comes back as failed rows with the generic message |
| T-04-22 | Tampering (integrity) | retry | low | mitigate | Retry resubmits only failed ids; the server's existing-link answer makes any repeat harmless (04-02) |
| T-04-SC | Tampering | npm/pip/cargo/Composer installs | high | mitigate | No package installs in this plan |
</threat_model>
