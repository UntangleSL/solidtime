## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gap in result rows and menu items, badge inset from block corner (`top-1 right-1`) |
| sm | 8px | Label-to-control gap, gap between the buttons of a footer, gap between controls on one form row (tags + billable, start + end) |
| md | 16px | Popover padding (`p-4`), gap between form groups (`space-y-4`), bar distance from the calendar's bottom edge |
| lg | 24px | not used by new markup |
| xl | 32px | not used by new markup (inherited `h-8` of `size="sm"` buttons) |
| 2xl | 48px | Floating selection bar height (`h-12`) |
| 3xl | 64px | not used |

Exceptions:
- Selection check badge: 16px (`size-4`, 12px `Check` inside) on blocks of tier T3 and above (32px or taller); 12px (`size-3`, 8px `Check`) on T1/T2 blocks. Both multiples of 4. Inset 4px from the top-right corner (`top-1 right-1`) on every tier; the 12px T1/T2 badge still fits inside a 16px block.
- Popover widths: single form and batch form `w-96` (384px); detail panel stays `w-80`; hover card stays `w-72`.
- Batch meeting list `max-h-40` (160px) with internal scroll; result rows 32px minimum (`min-h-8`).
- The bar's inner padding is `px-3 py-2` (12px / 8px): 12px is a multiple of 4 and matches the `px-3` of every existing button so the bar's left text lines up with button text.

## Layout and Interaction Contract

### 1. Where "Create time entry" appears (D-01, ASGN-01, roadmap criterion 6)

| Surface | Control | Opens |
|---------|---------|-------|
| Hover card (`OutlookMeetingHoverCard`, `actions` slot) | `PrimaryButton` `type="button"`, icon `ClockPlus`, label "Create time entry", right-aligned under the hint | Closes the card, opens the meeting's panel directly in **form mode** |
| Detail panel (`OutlookGhostDetail` footer) | Footer right: [ "Dismiss meeting" / "Restore meeting" outline `Button size="sm"` ] [ `PrimaryButton` `ClockPlus` "Create time entry" ]. Primary is last (rightmost) | Swaps the panel content to form mode in place (same anchor, width `w-80` to `w-96`) |
| Context menu (`OutlookMeetingContextItems`) | First action item under the subject label: `ClockPlus` "Create time entry" | Menu closes; after it has closed (existing `afterMenuClosed`), the panel opens in form mode (3.1 layering rule: no panel while the menu is open) |

Visibility rule: the action renders only when `canAct` is true (hidden, never disabled, in test-hook mode and while impersonating, D-13). Dismissed meetings (visible only with "Show dismissed meetings" on) show the action too; converting one clears its dismissal (D-11). Future meetings show it with no difference (D-09).

`data-testid`: `outlook-hover-create`, `outlook-detail-create`, `outlook-menu-create`.

### 2. Hover card delta

- Hint (12px `text-tertiary`): "Click for details. Ctrl+click to select several." with "⌘+click" on macOS (same platform detection as the 3.1 zoom tooltip). Hidden when `canAct` is false (keeps the old "Click for details").
- Actions row `mt-3 flex justify-end`: the single "Create time entry" PrimaryButton.
- Opening rules, delays, suppress-while list: unchanged. Additionally suppressed while a selection exists AND a modifier key (Ctrl/Cmd/Shift) is held, so the card does not flash during multi-select.

### 3. Single mini form (D-02, D-03)

Lives inside the meeting's existing Popover (`OutlookGhostDetail`), which gains a `mode: 'detail' | 'form'`. Anchor, side (`right`), align (`start`), `sideOffset` 8 and collision flipping are unchanged, so the form appears exactly where the panel appears. Non-modal popover, focus contained while open, not focus-trapped beyond reka defaults.

Layout, `w-96 p-4 space-y-4`, top to bottom:

1. **Header**: title "Create time entry" (13px 600, `id` used as the dialog `aria-labelledby`, replacing the subject label of detail mode). Under it the **context line** (12px `text-tertiary`, `tabular-nums`, truncate): `CalendarDays` 12px + "From Outlook · Tue, Nov 17 · 10:00 – 11:00" (date and range formatted like `OutlookMeetingSummary`'s time row, without duration).
2. **Description**: `TextInput`, full width, value = meeting subject (or empty when the subject is missing, never "(No subject)"), placeholder "What did you work on?" (core copy), `aria-label` "Description".
3. **Project and task**: `TimeTrackerProjectTaskDropdown` `variant="input"`, full width, `FieldLabel` "Project". Prefill: last project used for a meeting conversion, else the project of the user's most recent time entry, else empty (D-02). Task follows the core picker (empty by default).
4. **Tags and billable** on one row, `flex gap-2`: `TagDropdown` trigger ("Tags" / "1 Tag" / "N Tags") and the billable `Select` ("Billable" / "Non-Billable"). Billable follows the selected project's default and updates when the project changes (same watcher as the core modal); "Billable" item disabled under `billableRatesLocked`.
5. **Time**: `FieldLabel` "Start" and "End", two `TimePickerSimple` side by side (`grid grid-cols-2 gap-2`), followed by the duration (12px `text-tertiary`, `tabular-nums`, e.g. "1h 00min", via `formatHumanReadableDuration`). Dates are fixed to the meeting's own start and end dates; only times are edited (D-03). Edited times never change the meeting link.
6. **Inline error area** (only when a submit failed): `role="alert"`, 12px `text-destructive` with `CircleX` 12px, copy per Copywriting.
7. **Footer** `flex justify-end gap-2`: `SecondaryButton` "Cancel", `PrimaryButton` "Create entry" (`loading` while the request runs).

Keyboard and focus:
- On open, focus goes to the **"Create entry" button when a project is prefilled** (so a repeat conversion is: click "Create time entry", press Enter; D-02 "two clicks") and to the **project picker trigger when no project is prefilled**.
- Enter in the description submits; Enter on a focused button activates it; Ctrl/Cmd+Enter submits from any field. Enter inside an open picker dropdown is owned by the picker.
- Esc closes the open picker first; a second Esc closes the form and returns focus to the meeting block. "Cancel" does the same.
- Nested dropdowns (project, tags, billable select, time pickers) are reka layers inside the Popover; opening or clicking inside them must never close the form. Playwright acceptance: open form, pick a project, add a tag, change billable, change start time, assert the form is still open and the values are kept.

Validation (client, before any request):
- No project: inline `FieldError` under the picker "Choose a project." and focus moves to the picker. The Create button stays enabled (a disabled button hides the reason).
- End not after start: `FieldError` under the times "End time must be after start time."

Submit behaviour (pessimistic: the form is already open, so the user waits on it):
- While saving: "Create entry" shows the spinner and is disabled, other fields `disabled`, the popover cannot be dismissed by pointer-down outside (Esc is ignored until the request settles, at most the request time).
- Success (`created`, or the server returned the existing entry for an already converted occurrence, D-06): popover closes; meetings and time-entries queries are invalidated; the meeting disappears from the lane and the entry appears in the "My time" side; toast "Time entry created successfully" (core copy, same helper as manual creation); live-region announcement "Time entry created"; focus moves to the next meeting of that day, else the previous one, else the Sync button (same rule as Dismiss).
- Failure: form stays open with all values, the error area shows the mapped reason, focus moves to the "Create entry" button so a retry is Enter (the alert is read by its `role="alert"`).
- Double click / Enter repeat: the button is disabled after the first activation; the server unique link (D-06) is the real guard.

Lane geometry after conversion: when the converted meeting was the last meeting of that day, the lane disappears and the day column returns to full width (3.1 rule "days with no meeting render exactly as upstream"). Accepted; no animation.

### 4. Context menu delta

Items top to bottom (`min-w-[200px]`):
1. Label: subject (unchanged).
2. `ClockPlus` "Create time entry" (only when `canAct`).
3. `ListChecks` "Select meeting", or `X` "Deselect meeting" when the meeting is selected (only when `canAct`). This is the discoverable and keyboard path to multi-select.
4. `ExternalLink` "Open in Outlook" (unchanged, only with a valid https link).
5. Separator.
6. "Dismiss meeting" / "Restore meeting" (unchanged).

The menu always acts on the right-clicked meeting only, even when a selection exists.

### 5. Multi-select (D-07)

| Input | Effect |
|-------|--------|
| Ctrl-click (Windows/Linux) or Cmd-click (macOS) on a block | Toggles that meeting in the selection and makes it the range anchor. Does not open the panel. Closes any open panel and hover card first. (On macOS, Ctrl-click is the system context menu and opens the meeting menu; that is expected) |
| Shift-click on a block | Adds every rendered meeting whose start lies between the anchor's start and the clicked meeting's start (inclusive, across the visible days, ordered by start then id) to the selection. Without an anchor it behaves like Ctrl/Cmd-click |
| Ctrl/Cmd+Enter on a focused block | Toggles it (keyboard equivalent of Ctrl/Cmd-click) |
| Shift+Enter on a focused block | Range-adds to it (keyboard equivalent of Shift-click) |
| Context menu "Select meeting" / "Deselect meeting" | Toggles it |
| Plain click on a block | Clears the selection, then opens that meeting's panel (normal behaviour) |
| Click on empty grid, on a time entry, or anywhere outside blocks, the bar, its popover and their nested dropdowns | Clears the selection |
| Esc | Closes the open popover if any; otherwise clears the selection |
| Week / day navigation, view change | Clears the selection |
| A selected meeting disappears after a sync | It is dropped from the selection silently; the count updates |

Selected block visual: hover fill at rest, 2px ring (`ring-accent-700` / `dark:ring-accent-200`, `ring-offset-0`) and the check badge in the top-right corner (sizes in Spacing). The badge is `aria-hidden`; the block's `aria-label` gains the suffix ", selected" and the block gets `aria-pressed="true"` while selected (`"false"` otherwise, only while a selection exists). `data-selected` attribute for tests. Dismissed blocks can be selected: they keep their dotted style and get the ring and badge.

Selection and panel never coexist: Ctrl/Cmd/Shift-click closes any open panel; a plain click (which opens a panel) clears the selection.

`canAct` false: modifier clicks behave like plain clicks; no selection, no bar.

### 6. Floating selection bar (D-07)

Shown while at least one meeting is selected (and while a batch result view is open, see 7).

| Property | Contract |
|----------|----------|
| Placement | Horizontally centred on the calendar grid area (not the viewport, so the sidebar does not offset it), 16px above the bottom of the calendar's visible area, does not scroll with the grid. `z-40`: above blocks, entries and the now line, below popovers and toasts (`z-50`) |
| Surface | `h-12 px-3 py-2 rounded-lg border bg-popover text-popover-foreground shadow-dropdown flex items-center gap-2` |
| Content | Left: "3 meetings selected" (13px 400, `tabular-nums`). Right: `PrimaryButton` `ListChecks` "Assign 3 meetings", then a ghost icon `Button` (`size="icon"`, 36px) with `X` and `aria-label` "Clear selection" |
| Semantics | `role="toolbar"`, `aria-label` "Meeting selection". Selection count changes are announced in the existing polite live region ("3 meetings selected"; "Selection cleared" when it empties) |
| Motion | Appears with the existing `animate-in fade-in-0 slide-in-from-bottom-2` under `motion-safe`, instant under reduced motion |
| Narrow screens | Under 480px wide the count text is hidden and only the two buttons remain (the button label carries the count) |
| Test ids | `outlook-selection-bar`, `outlook-selection-assign`, `outlook-selection-clear` |

### 7. Batch mini form and results (D-07, D-08, ASGN-04)

"Assign N meetings" opens a Popover anchored to the bar (`side="top"`, `align="center"`, `sideOffset` 8), `w-96 p-4 space-y-4`:

1. **Header**: title "Assign 3 meetings" (13px 600).
2. **Meeting list** (`max-h-40 overflow-y-auto`, `role="list"`): one row per selected meeting in start order, `min-h-8 flex items-center gap-2`: status slot (empty before submit), subject (12px 600, truncate), then date and range right-aligned (12px 400 `text-tertiary`, `tabular-nums`, "Tue 10:00 – 11:00").
3. **Project and task**, **Tags and billable**: identical controls and prefill rules to the single form.
4. **Note** (12px `text-tertiary`): "Each meeting keeps its own time, and its subject becomes the description." No description field and no time fields (D-07).
5. **Footer**: `SecondaryButton` "Cancel", `PrimaryButton` "Create 3 time entries".

Focus on open: same rule as the single form (Create button when a project is prefilled, else the project picker). Same validation for the project.

While submitting: each row's status slot shows `LoadingSpinner` (12px) until its result arrives; the button shows its spinner; the controls are disabled. Rows resolve independently (one batch endpoint or several calls, either way the UI receives one result per meeting).

Result per row (status slot icon 16px, reason as a second line under the subject, 12px `text-secondary`):
| Result | Icon | Second line | Lane | Selection |
|--------|------|-------------|------|-----------|
| Created | `CircleCheck` green | "Created" | Meeting disappears | Removed |
| Already converted (server returned the existing entry, D-06) | `Info` `text-tertiary` | "Already had a time entry" | Meeting disappears | Removed |
| Failed | `CircleX` `text-destructive` | mapped reason (Copywriting) | Meeting stays | Stays selected (D-08) |

After all rows settle:
- **Every row created or already converted**: the popover closes, the selection is empty so the bar hides, toast "3 time entries created successfully" (count of created plus already converted), live announcement the same. The per-meeting outcome is visible in the lane (each one left it).
- **At least one failure**: the popover stays open in result view. Header becomes "2 of 3 time entries created" ("No time entries created" when none succeeded), announced politely. Rows keep their status and reasons. Form controls re-enable with the values kept. Footer: `SecondaryButton` "Close", `PrimaryButton` "Retry 1 failed" / "Retry 2 failed" (resubmits only the failed rows with the current form values). "Close" closes the popover; the bar stays with the failed meetings still selected ("Assign 1 meeting").
- Focus: in result view, focus moves to the header (`tabindex="-1"`) so screen readers read the summary; Tab reaches "Retry".

Test ids: `outlook-batch-form`, `outlook-batch-row` (with `data-status="pending|created|existing|failed"`), `outlook-batch-submit`, `outlook-batch-retry`.

### 8. Converted time entry in the calendar (D-04, D-05, ASGN-05)

- The entry block is a normal entry (project colour, border, `shadow-card`, drag, resize, edit, delete, context menu all unchanged).
- Origin marker: a `CalendarDays` icon, 12px (`w-3 h-3 shrink-0`), as the first item of the title row in `FullCalendarEventContent`, in the same slot and size the break `Coffee` icon uses; colour inherits the entry text colour (never accent, never Microsoft blue). With `title="Created from an Outlook meeting"` and an `sr-only` span with the same text so the entry's accessible name ends with it.
- Core seam: one additive optional prop on `FullCalendarEventContent` (e.g. `isFromMeeting?: boolean`), passed through `CalendarDayColumn` from the event's extended props; the fork supplies which entry ids are meeting-linked. Ledgered in `docs/m365/TOUCHED-CORE-FILES.md` (D-12). Other views (Time list, Timesheet, Reporting) are unchanged **(default)**.
- Editing times, project or description keeps the icon (the link survives, D-05). Deleting the entry: after the delete succeeds the meetings query is invalidated and the meeting reappears in the lane as a suggestion on its own (no extra toast beyond the core "Time entry deleted successfully").

### 9. Keyboard and screen-reader summary

- Every action has a keyboard path: Enter on a block opens the panel, which has "Create time entry"; the context-menu key / Shift+F10 opens the meeting menu with "Create time entry" and "Select meeting"; Ctrl/Cmd+Enter and Shift+Enter select; the bar is in the Tab order after the calendar grid.
- Live region (existing `outlook-announcement`, polite): "Time entry created", "3 meetings selected", "Selection cleared", batch summaries. Never per-row during a batch.
- `prefers-reduced-motion`: bar and popover transitions use `motion-safe:`.
