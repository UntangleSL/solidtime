## Phase Goal

**As a** team member tracking time, **I want to** see my Outlook meetings as suggestions in the solidtime calendar, **so that** I can see which meetings still need logging without switching to Outlook.

<objective>
Backend tracer of Phase 3: a connected user's Outlook meetings for a range travel from Microsoft Graph `calendarView` (literal URL, combined `Prefer` header on every page, `nextLink` followed verbatim with a host check) through the fail-closed eligibility filter into the new `outlook_meetings` cache, and come back out of a read endpoint that never calls Graph. The research decision "database cache, read endpoint plus separate sync endpoint" (03-RESEARCH Decision 1 and 2) is built for keeps here; refresh, resilience, dismissal and the calendar UI are later plans that plug into these seams.

Purpose: SYNC-01 (read path that never blocks), SYNC-03 (eligibility), SYNC-04 (UTC storage) and CAL-03 (owner scoping) proven against the real Phase 1 fixtures before any UI exists.
Output: two tables, the Graph client, eligibility, token seam, sync service, two session routes, resource, fixture test support and four test classes green in CI.

Assumption-delta decision (recorded for the phase): no-change. The phrase "another user's meetings" is privacy wording; the identity model (user + tenant-pinned Microsoft account, one primary calendar) is unchanged; shared calendars stay v2 SYNC2-02.
</objective>
