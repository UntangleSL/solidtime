## Spacing Scale

Declared values (multiples of 4, Tailwind units in parentheses):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`1`) | Icon-to-text gap inside a ghost block, gap between status icon and text |
| sm | 8px (`2`) | Gap between toolbar controls, gap between popover meta rows, gap between popover action buttons |
| md | 16px (`4`) | Popover padding (`p-4`), space above the popover footer (`mt-4`) |
| lg | 24px (`6`) | Not used by new markup (reserved) |
| xl | 32px (`8`) | Toolbar control height (`h-8`, existing) |
| 2xl | 48px (`12`) | Not used by new markup (reserved) |
| 3xl | 64px (`16`) | Not used by new markup (reserved) |

Exceptions:
- Ghost block minimum height is 16px (a meeting shorter than 15 minutes is still drawn and clickable). The 44px touch-target rule does not apply inside a time grid; this matches existing time entries. Keyboard access (Tab, Enter, Space) is the equivalent path.
- 1px borders and the 2px focus ring are inherited from the existing system; they are not declared spacing values.
- Ghost horizontal placement declares NO spacing value of its own (route taken for the 2px issue: inherited geometry, not a new token). The ghost layer must align edge-to-edge with the existing time entries, so it reuses the core event container geometry verbatim: the same horizontal offsets that `CalendarDayColumn.vue` applies to its events container (the default offset, plus `left: 8px` or `left: 204px` when activity status is on in week or day view). The slot content copies these offsets from slot props because the scoped CSS does not reach slot content. A 4px substitute would misalign ghosts against entries by 2px per side, so none is used. Planner: copy the class and offset values from `CalendarDayColumn.vue` rather than writing new ones.
- Popover width is 320px (`w-80`).

## Typography

Exactly three sizes and two weights are declared for new markup. Sizes are the existing theme sizes (`tailwind.theme.js`).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Ghost block text (subject, time) | 10px (`text-2xs`) | 600 for subject, 400 for time | 12px (1.2) |
| Meta and status (status line, popover eyebrow, popover meta rows, helper text, link) | 12px (`text-xs`) | 400 | 16px (1.33) |
| Button label (inherited from `Button size="sm"`: Sync, Dismiss, Restore, Connect, Reconnect) | 12px (`text-xs`) | 500 (inherited `font-medium`) | 16px (1.33) |
| Body and heading (popover subject, setting label, button label) | 13px (`text-sm`) | 600 for the popover subject and the setting section heading, 400 elsewhere | 18px (1.4) |

- Weights: new text uses regular 400 and semibold 600. Weight 500 is declared only for button labels, inherited from the existing `Button` component (`font-medium`); no other new markup sets 500.
- Ghost text 10px mirrors the existing time entry content (`FullCalendarEventContent.vue`, `text-2xs`). It is acceptable only because the full subject and times are always reachable in the popover and in the block's `aria-label`.
- Body line-height is at least 1.33 and heading line-height 1.4 (the theme pairs fixed line-heights with each size; use the theme pairing, do not override).

## Color

All values are theme tokens; hex is given for light mode and oklch for dark mode as the resolved reference.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-default-background` (light `#fcfcfc`, dark `oklch(0.17 0 0)`) | Calendar grid surface, toolbar |
| Secondary (30%) | `bg-popover` and `bg-card-background` (light `#ffffff`, dark `oklch(0.20 0 0)`); `--color-bg-tertiary` (light `#eeeeef`, dark `oklch(0.25 0 0)`) for the ghost fill | Detail popover, settings popover, ghost fill |
| Accent (10%) | `accent-500` light / `accent-400` dark (sky, `#0ea5e9` / `#38bdf8`) | Reserved list below |
| Destructive | not used in this phase | Dismiss is reversible, so it is NOT styled destructive |

Accent reserved for (and nothing else; exactly these three):
1. The 2px outline of the ghost whose detail popover is currently open.
2. The spinning `RefreshCw` icon while a sync is in progress.
3. The "Open in Outlook" link text and its external-link icon in the popover.

Other color rules:
- Ghost border: `1px dashed`, color `text-text-tertiary` (light `#57575c`, dark `oklch(0.70 0 0)`). This keeps the boundary above the 3:1 non-text contrast minimum in both themes. Do NOT use `border-border` or `text-quaternary` for the dashed border (too faint in light mode).
- Ghost fill: `background-color: color-mix(in srgb, var(--color-bg-tertiary) 55%, transparent)` so grid lines remain visible. Hover raises the mix to 80% and the border to `text-text-primary`.
- Ghost text: `text-text-secondary` for the subject and `text-text-tertiary` for time and organizer. Contrast stays at or above 4.5:1 on the ghost fill in both themes. Never reduce text contrast with `opacity`.
- Ghosts must NOT use the project color palette, the sky activity-box tint (`rgba(14,165,233,…)` already used by the activity status boxes), or the amber break hatch (`rgba(217,119,6,…)`). The ghost is deliberately neutral so it cannot be mistaken for a time entry, an activity period, or a break.
- Warning marker (Outlook unavailable, Reconnect Microsoft): `TriangleAlert` icon in the amber exception pair below. Text next to it stays `text-text-tertiary`.
- The checked "Show dismissed meetings" switch uses the existing `bg-primary` token of the shared `Switch`; it is not part of the accent list and must not be restyled.
- Explicit exception to the 60/30/10 accent budget: the amber warning pair `text-amber-600 dark:text-amber-400` reuses the existing calendar warning classes (the same pair as `calendar_break_placement_hint` in `FullCalendarEventContent.vue`). It is not a new color and is used only on the `TriangleAlert` icon.
- No Microsoft brand blue anywhere (it would collide with the sky accent and project colors).

### Dismissed variant (only rendered when "Show dismissed meetings" is on)

- Border `1px dotted` in `text-text-tertiary` (dotted, not dashed, is the second non-color cue).
- Fill mix drops to 25%.
- Leading icon is `EyeOff` instead of `CalendarDays`.
- Subject and time keep `text-text-tertiary` (no strikethrough, no opacity on text). `aria-label` ends with ", dismissed".

## Layout and Interaction Contract

### 1. Ghost blocks (week and day views)

Rendering layer
- Rendered through the `overlay` slot of `CalendarDayColumn`, as the **first child** of the column root, so every real `.fc-event`, the selection rectangle (`z-[2]`), the now indicator (`z-50`) and the activity boxes (`z-10`) paint above it.
- The layer container is `pointer-events-none`; each ghost is `pointer-events-auto`.
- Each ghost carries `data-calendar-overlay`, class `m365-ghost`, `role="button"`, `tabindex="0"`, `aria-haspopup="dialog"`, `aria-expanded` bound to the popover state, `select-none`. It carries NONE of: `.fc-event`, `data-event-id`, `.fc-timegrid-col`, `touch-none`, resizer children. The ghost is never draggable or resizable, never starts a slot selection (the core `onSlotPointerDown` ignores `[data-calendar-overlay]`), and clicking it only toggles its popover.
- Layer container: `role="group"` with `aria-label="Outlook meetings, {weekday} {date}"`, rendered only when that day has at least one ghost.

Geometry
- Top and height from the same `minutesToPixels` the entries use; clipped to the day (`dayStart` to `dayEnd`) and to the visible `startHour` to `endHour`. A ghost that continues across midnight gets square corners on the clipped side (`rounded-t-none` / `rounded-b-none`), like entries.
- Minimum height 16px.
- Concurrent ghosts: greedy lane assignment, width `100% / lanes`, capped at 3 lanes; a 4th or later overlapping ghost shares lane 3 and stacks on top in start-time order (known limitation, see UI Considerations).
- Rounded `rounded-sm`, no shadow (entries use `shadow-card`; the absence of elevation is part of the "not a real entry" cue).

Content by available height (all text truncates with ellipsis, single line each)
| Block height | Week view | Day view |
|--------------|-----------|----------|
| under 24px | `CalendarDays` 12px + subject | same |
| 24px to 39px | adds nothing; subject only | subject + time range inline |
| 40px and over | subject, then time range (e.g. `10:00 – 11:00`) | subject, time range, then organizer name |
| any height, online meeting | trailing `Video` 12px icon pinned right | same |

- Leading `CalendarDays` icon (12px, `text-text-tertiary`) is the non-color marker that the block is an Outlook suggestion.
- Subject missing or empty: show "(No subject)".
- Time format follows the organization setting (`formatTime(start, timeFormat)`), in the user's solidtime timezone via `getLocalizedDayJs`.
- Hover: border and fill change as in Color; cursor `pointer`. Focus-visible: `ring-2 ring-ring ring-offset-1` (identical to entries). Popover open: `ring-2 ring-accent-500` (accent item 1).
- `aria-label`: `"{subject}, {start} to {end}, Outlook meeting suggestion"`; dismissed variant appends `", dismissed"`.

### 2. Detail popover (`OutlookGhostDetail`, extensible)

- Built with `Popover` / `PopoverContent`, trigger is the ghost itself (`as-child`). Opens on click, Enter or Space. Closes on Esc, outside click, or action completion. Esc and close return focus to the ghost.
- `PopoverContent`: `w-80 p-4`, `side="right"` in week view and day view with automatic collision flip, `align="start"`, `sideOffset` 8. Non-modal.
- `role="dialog"` (Reka default) with `aria-labelledby` pointing at the subject element.

Content, top to bottom (rows separated by 8px, `gap-2`)
1. Eyebrow (12px, `text-text-tertiary`): `CalendarDays` + "Outlook meeting"; when dismissed: "Outlook meeting · Dismissed".
2. Subject (13px, 600, `text-text-primary`, `line-clamp-3`, `break-words`). Empty subject: "(No subject)".
3. Time row: `Clock` + `Tue, Oct 27 · 10:00 – 11:00 · {duration}` (12px, `text-text-secondary`). A meeting that spans midnight shows both dates: `Mon, Oct 26 22:00 – Tue, Oct 27 01:00 · {duration}`. Duration via `formatHumanReadableDuration` with the organization's interval format.
4. Organizer row (only when the organizer name is present): `User` + "Organized by {name}", or "You are the organizer" when `is_organizer` is true.
5. Online row (only when `is_online_meeting`): `Video` + "Online meeting". D-20 forbids any location text; no location, address, attendee list, or body is shown. The label is "Online meeting" (not "Teams") because the binding `$select` carries no provider field, so the panel cannot assert Teams.
6. "Open in Outlook" (only when `web_link` is a valid `https` URL): accent-colored link with `ExternalLink` 12px, `target="_blank" rel="noopener noreferrer"`, with visually hidden suffix "(opens in a new tab)". Otherwise omit the row.
7. `Separator`, then footer actions (`mt-4`, `flex justify-end gap-2`).

Footer actions
- Default state: `Button variant="outline" size="sm"` "Dismiss meeting".
- Dismissed state: `Button variant="outline" size="sm"` "Restore meeting".
- Extension points for later phases (declared now, rendered empty now): named slots `meta` (extra rows after the Online row), `actions` (rendered after "Dismiss meeting", right-aligned; Phase 4 puts the primary "Assign to project" button here, Phase 5 series actions in a "More" menu here), `footer-note` (12px note under the actions). The component takes the meeting object as a prop and emits `dismiss` and `restore`; it owns no network code.

Dismiss and Restore behavior
- Optimistic: the popover closes immediately and the ghost updates in place (removed when "Show dismissed" is off; switched to the dismissed variant when it is on). No success toast (the result is visible). No confirmation dialog.
- Failure: revert the ghost and show an error notification (`addNotification('error', …)`), copy below.
- Focus after Dismiss when the ghost disappears: move to the next ghost in DOM order in the same day; if none, to the toolbar Sync button. When the ghost stays (dismissed variant), focus returns to it.
- A polite live-region announcement accompanies each action: "Meeting dismissed" / "Meeting restored".

Focal point of the calendar screen
- The focal point stays the time grid with the user's time entries (project-colored, solid, elevated). Ghosts are intentionally lower in the visual hierarchy: neutral, dashed, flat, behind entries. The toolbar Outlook cluster is a secondary control, outlined and small, never filled; nothing in this phase uses a primary (filled) button on the calendar screen.
- The one element that may draw the eye is the amber warning icon (unavailable or reconnect), and only while the condition exists.

### 3. Toolbar controls (`OutlookCalendarControls`, injected through the toolbar `extra` slot)

Placement: inside the right-hand cluster of `CalendarToolbar`, before the week/day tabs: `[status text] [Sync | Connect | Reconnect]  [week|day tabs]  [settings]`, all `flex items-center gap-2` (8px), all controls `h-8`.

Responsive collapse (resolved, not left to the implementer)
| Viewport | Status text | Sync / Connect / Reconnect | Unchanged |
|----------|-------------|----------------------------|-----------|
| 1024px and up (`lg`) | Visible, `max-w-64`, ellipsis | Labelled: "Sync Outlook", "Connect Microsoft 365", "Reconnect Microsoft" | Date navigator, week/day tabs, settings |
| 768px to 1023px (`md`) | `sr-only` plus Sync tooltip; amber icon stays visible when unavailable | Labelled as above | same |
| under 768px | `sr-only` plus tooltip; amber icon stays | Icon-only (`w-8 p-0`) with `aria-label` ("Sync Outlook meetings", "Connect Microsoft 365", "Reconnect Microsoft") and a Tooltip with the same text | same |
- Collapse order is always status text first, then button labels. The date navigator, tabs and settings button never collapse because of this cluster.

Visibility by connection state (from the Inertia shared `calendar.state`)
| State | Controls shown |
|-------|----------------|
| integration off, or an admin is impersonating (no `calendar` block in the shared props) | Nothing at all: no Sync, no Connect, no toggle, no ghost layer. Impersonation must never expose a Connect or Reconnect button (it would start OAuth for the impersonated user). Planner: the shared prop must be omitted in both cases |
| `not_connected` | "Connect Microsoft 365" button occupies the Sync control's position. Sync and the status text are not rendered (no dead disabled control) |
| `reconnect` | "Reconnect Microsoft" button with amber `TriangleAlert`, in the Sync control's position, plus the status text for this state. Last known meetings (if the read endpoint returns any) stay visible |
| `connected` | Status text + Sync button |

Sync button
- `Button variant="outline" size="sm"`, `RefreshCw` 16px + visible label "Sync Outlook". Below the `md` breakpoint (under 768px) the label is hidden and the button is icon-only (`w-8 p-0`) with `aria-label="Sync Outlook meetings"` (contains the visible label, per WCAG label-in-name) and a Tooltip "Sync Outlook meetings".
- Idle: enabled. Syncing: `aria-busy="true"`, disabled, icon `motion-safe:animate-spin` in accent color. Cooldown: disabled for 10 s after a completed sync and while `retry_after` is pending (the timings are those in RESEARCH Pattern 4; the UI only reflects them).
- Pressing Sync never opens a dialog and never blocks the grid. Time entries stay interactive in every state.

Status text (12px, `text-text-tertiary`, single line, `max-w-64` with ellipsis; the full text is in its tooltip)
- Rendered inside a persistent `role="status"` `aria-live="polite"` region so changes are announced once per state change (never per tick).
- Visible text is shown from the `lg` breakpoint up; below `lg` (1024px) it is `sr-only` and its content is exposed as the Tooltip of the Sync button, while the amber `TriangleAlert` icon stays visible for the unavailable state.
- Times use the organization time format in the user's timezone: same day shows only the time; otherwise the short date and time.

Connect and Reconnect
- "Connect Microsoft 365": `Button variant="outline" size="sm"` with `Link` icon. Navigates with `navigateTo` to the Phase 2 connect URL (`?intent=connect`, return target `calendar`). It is not an Inertia visit.
- "Reconnect Microsoft": same component, amber `TriangleAlert` icon, same destination.
- If the user returns from a failed connect, show the Phase 2 error copy (`microsoft365.error.*`) as an error notification on the calendar; the calendar itself needs no error banner.

### 4. "Show dismissed meetings" (calendar settings popover)

- Added as a section at the bottom of `CalendarSettingsPopover` through a new slot (`settings-extra`), after a `Separator`. Rendered only for states `connected` and `reconnect`.
- Layout: heading "Outlook meetings" (13px, 600); below it a `Field` with `FieldLabel` "Show dismissed meetings" and the `Switch` right-aligned on the same row (`flex items-center justify-between`), and `FieldDescription` (12px) "Dismissed meetings appear faded so you can restore them."
- Default off. The choice is remembered per browser (localStorage); it is a view preference, not a server setting.
- Switch has `role="switch"` via Reka, `aria-checked` state, label association via `for`/`id`, standard focus ring.
- Toggling refetches the meetings read (no Graph call, no sync status change).

### 5. States on the calendar

| State | What the user sees |
|-------|--------------------|
| First load | Grid and time entries render exactly as today. The meetings read is fast and silent. If a sync starts, the status line shows "Syncing Outlook…" and the Sync icon spins; ghosts fade in when the read resolves (no skeleton blocks, no layout shift) |
| Meetings present | Ghost blocks as above; status "Last synced 14:32" |
| No meetings in range | No ghost layer; the status area reads "No Outlook meetings in this range · Last synced 14:32" in plain `text-text-tertiary` (no warning icon) |
| Graph unavailable, slow, throttled (429) | Cached ghosts stay; amber icon and "Outlook unavailable, retry later"; Sync disabled until retry is allowed. Time entries unaffected |
| No mailbox (F1 or freelance user) | No error styling; status "No Outlook calendar for this account" (no amber icon); Sync stays enabled |
| Token cannot be refreshed | "Reconnect Microsoft" button as above, no error banner (SEC-02) |
| Not connected | "Connect Microsoft 365" button only; calendar works exactly as today |
| Integration off or impersonating | Nothing Outlook-related rendered |

### 6. Keyboard and screen-reader access

- Tab order inside a day: ghosts (first in DOM) then entries. Ghost: Enter or Space opens the popover; Esc closes and restores focus to the ghost. In the popover, Tab moves through the link, then Dismiss meeting or Restore meeting, then any slotted actions. The popover is non-modal, so Reka's default applies: tabbing past the last control or pressing Esc closes it.
- Every control has a visible focus indicator (`ring-2 ring-ring`), minimum 3:1 against its background in both themes.
- Information never relies on color alone: dashed or dotted border, leading icon, and `aria-label` carry the ghost and dismissed meaning; the amber icon is always paired with text (visible or in the tooltip and live region).
- Spinner and popover animations respect `prefers-reduced-motion` (`motion-safe:` on the spin; Reka animations already collapse with the user setting).
- All new strings are English (Phase 2 D-18); Spanish mirror keys are added in `lang/es` in the same task (`MicrosoftLangTest` parity).
