## Phase Goal

**As a** team member tracking time, **I want to** see my Outlook meetings as suggestions in the solidtime calendar, **so that** I can see which meetings still need logging without switching to Outlook.

<objective>
SEC-02 on the backend: the access token stored at sign-in is refreshed silently with the documented refresh-token grant (tenant-pinned v2 endpoint, row lock, 120 s skew, rotation written atomically), and a refresh that cannot succeed is classified so that only user-fixable failures (invalid_grant and friends) become the "Reconnect Microsoft" state, while an operator error such as an expired client secret never sends every user to Reconnect (03-RESEARCH Pattern 1, Pitfall 7). Graph 401/403 get one forced refresh and one retry.

Purpose: meetings keep syncing past the one-hour access-token lifetime, and the UI (03-07, 03-08) gets a reliable `reconnect` signal.
Output: one migration (two nullable columns), token service refresh, client 401 retry, account state helper, resolver/controller marker resets, MicrosoftTokenRefreshTest green in CI.
</objective>

|----------|-------------|
| Server -> login.microsoftonline.com | Client secret and refresh token leave the server in the refresh grant |
