## Phase Goal

**As a** fork maintainer, **I want to** have Untangle's Entra app registration consented and real Outlook calendar responses recorded, **so that** sign-in and meeting sync are built on verified tenant facts instead of assumptions.

This plan builds the capture side of that goal before any tenant exists: the tool that will prove the registration works and record real `calendarView` responses, proven end-to-end against a local fake of Entra and Graph.

<objective>
Build the zero-dependency Node capture harness `tests/Tools/m365-spike/capture.mjs` (D-05; Claude's-discretion choice of a raw OAuth code flow instead of Socialite): `auth`, `auth --expect-blocked`, `capture --round A|B` and `status`, with the raw/ output layout that 01-03's sanitizer consumes.

Purpose: as soon as the admin hands back credentials, the registration can be verified (SETUP-01 criterion 2) and the fixtures captured (SETUP-02) without writing any more code under time pressure.
Output: harness, fake Microsoft test server, node:test suites, nested .gitignore, .env.local.example, README.
</objective>
