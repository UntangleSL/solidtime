## Phase Goal

**As a** fork maintainer, **I want to** have Untangle's Entra app registration consented and real Outlook calendar responses recorded, **so that** sign-in and meeting sync are built on verified tenant facts instead of assumptions.

This plan makes the recorded responses safe to commit and checkable: the sanitizer, the manifest with its file index, and the fixture gate including a Node replay of the paged fixtures, all proven offline before real data exists. The decision-document gate is built in parallel by 01-04.

<objective>
Build the offline half of the capture pipeline (D-05; the manifest's `experiments` summaries are the D-06 evidence base): `sanitize.mjs` (raw/ → tests/Fixtures/M365/ with an indexed manifest) and `validate-fixtures.mjs` (schema with an orphan check over the manifest file index, hypothesis-neutral semantic predicates, leak scan, Node replay of every complete calendarView page sequence), each with node:test coverage including an end-to-end run fake capture → sanitize → validate.

Purpose: Round A can be sanitized and gated the moment it is captured, and the replay check proves the committed pages walk as an Http::fake-style sequence on a Node-only host, long before raw/ is deleted.
Output: sanitizer + scenarios modules, two CLIs, three test files, fixture README.
</objective>
