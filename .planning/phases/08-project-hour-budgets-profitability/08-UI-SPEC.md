# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Brownfield and token-driven. This phase adds a fork module (`resources/js/profitability/`) with one new page, one summary card on the project page, four editors and one settings area. It adds no UI library, no package and no new design token: every colour, size and spacing value below already exists in `tailwind.theme.js`, `styles.css` or the Phase 3.2 `untangle-theme.css`. Sources: 08-CONTEXT.md D-01..D-19, REQUIREMENTS BUDG-01..07 and CHRG-01..03, 08-RESEARCH.md (structure, AccessScope, projection formulas, assumptions A1..A11), 03.2-UI-SPEC.md (approved tokens, typography, accent rules), and code read on 2026-11-27 (`ProjectShow.vue`, `AppLayout.vue`, `ReportingChart.vue`, `ReportingTabNavbar.vue`, `StatCard.vue`, `Card.vue`, `PageTitle.vue`, `TableHeading.vue`, `ProjectTable*.vue`, `EstimatedTimeProgress.vue`, `TabBar.vue`, `Badge.vue`, `DialogModal.vue`, `BillableRateInput.vue`, `DatePicker.vue`). Contrast values quoted were computed with a WCAG 2.x script on 2026-11-27, not estimated; the two-series chart palette was run through the `dataviz` validator.
>
> The owner is non-technical and all functional decisions are locked. Every design choice not covered by CONTEXT is recorded here as a decision (prefix **UI-Dn**) with its reason, so the planner and executor do not need to ask.

## Spacing Scale

Declared values (multiples of 4, Tailwind units in parentheses):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`1`) | Icon-to-text gap in pills and buttons; mini meter track height (`h-1`) |
| sm | 8px (`2`) | Gap inside a KPI tile; gap between a meter and its caption; meter track height on the summary card (`h-2`) |
| md | 16px (`4`) | Gap between KPI tiles (`gap-4`); dialog field gap; cell horizontal padding in new table columns (`px-4`) |
| lg | 24px (`6`) | Section padding and gap between stacked cards (`space-y-6`, `pt-6`, same as `ProjectShow.vue`) |
| xl | 32px (`8`) | Height of a bar row in the horizontal charts; touch-height of icon buttons (`h-8 w-8`) |
| 2xl | 48px (`12`) | Empty-state vertical padding (`py-12`) |
| 3xl | 64px (`16`) | Not used by new markup |

Exceptions:
- Existing components keep their own internal padding (StatCard `px-3.5 py-2.5`, TableHeading rows, Badge, Button sizes); new markup does not restyle them.
- Meter reference ticks are 2px wide and 16px tall (`w-0.5 h-4`), centred on an 8px track so they stand 4px above and below it; on the 4px table meter the tick is 2px x 12px. Both are drawn marks, not spacing values.
- Chart heights: planned-vs-consumed 240px; chargeability and client-margin charts 32px per bar row plus 48px for the axis (all multiples of 4).
- Touch targets: row overflow button and delete-row icon buttons are 32px square (above the WCAG 2.5.8 24px minimum).

## Typography

Exactly four sizes and two weights for new markup, all existing theme sizes and line heights (this phase adds no override). Identical to the Phase 3.2 contract.

Size source (verified 2026-11-27): solidtime overrides Tailwind's default font scale. `tailwind.config.js` line 21 spreads `...solidtimeTheme` into `theme.extend`, and `resources/js/packages/ui/tailwind.theme.js` lines 18-27 define `xs: ['0.75rem', { lineHeight: '1rem' }]` (12px/16px), `sm: ['0.8125rem', { lineHeight: '1.125rem' }]` (13px/18px), `base: ['0.9375rem', { lineHeight: '1.375rem' }]` (15px/22px) and `xl: ['1.25rem', { lineHeight: '1.75rem' }]` (20px/28px). The class names below therefore render the pixel sizes stated, not the Tailwind defaults (14px `sm`, 16px `base`).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (table cells, form inputs, dialog text) | 15px (`text-base`) | 400 | 22px (1.47) |
| Label (column headers inherit `TableHeading` 12px; field labels, KPI captions, tab labels) | 13px (`text-sm`) | 400 | 18px (1.38) |
| Caption (meter captions, helper text, pill text, chart axis labels, "as of" lines) | 12px (`text-xs`) | 400; pills 600 | 16px (1.33) |
| Heading (KPI values, card and dialog titles, page title via AppLayout) | 20px (`text-xl`) | 600 | 28px (1.4) |

Rules:
- Every number (hours, money, percent, dates in tables) uses `tabular-nums` and is right-aligned in table columns; text columns are left-aligned.
- Reused components keep their inherited weights (StatCard value is `font-medium`, `CardTitle`, `DialogModal` title); new markup introduces no weight other than 400 and 600.
- Chart text: ECharts `fontFamily: 'Inter, sans-serif'`, `fontSize: 12`, `fontWeight: 400`, colour `--color-text-secondary` (same as `ReportingChart.vue`).

### Number formats (UI-D1)

| Quantity | Format | Example |
|----------|--------|---------|
| Hours | Decimal hours, at most 1 decimal, trailing `.0` dropped, organization number format, suffix ` h` | `120 h`, `12.5 h`, `1,240 h` |
| Negative hours (over sold) | Never a bare minus: written as words | `6 h over` |
| Money | `formatCents(cents, currency, currency_format, currency_symbol, number_format)` unchanged | `€12,400.00` |
| Negative money (loss) | Minus sign from `formatCents` plus the loss colour (sign is the non-colour cue) | `−€1,250.00` |
| Percent | Integer, no decimals, ` %` per number format | `68 %` |
| Percentage-point gap | Signed integer with `pp` | `−7 pp` |
| Month | `MMM YYYY` via dayjs in the app locale | `Nov 2026` |
| Period | Monthly `Nov 2026`; quarterly `Oct – Dec 2026`; annual `Jan – Dec 2026`; stub `15 – 30 Nov 2026`; one-off `15 Nov 2026 – 31 Mar 2027` | |

Reason: hours in decimal (not `hh:mm`) because budgets are sold and planned in whole and half hours; the existing reporting duration format stays elsewhere.

## Color

Dominant, secondary and accent follow the Phase 3.2 split; no token is added or changed.

| Role | Dark | Light | Usage |
|------|------|-------|-------|
| Dominant (60%) | `#1C1C1C` (`--color-bg-primary`) | `#F9FCFD` | Page content surface |
| Secondary (30%) | `#262626` cards and inputs, `#141414` sidebar, `#2C2C2C` dialogs | `#F9FCFD` cards with `#DDDDDD` border, `#EEF4F5` sidebar | Cards (`Card`, `StatCard`), table header rows, dialogs, meter tracks (`bg-quaternary`) |
| Accent (10%) | preset step 300 (Untangle `#00F5D4`) via `--theme-color-chart`; meters step 200 | preset step 400 (Untangle `#007C6B`); fills step 500 | Reserved list below |
| Destructive | existing `--destructive` | same | Delete-row confirmation button and form error text only |

Accent reserved for (and nothing else):
1. Primary buttons: "Set contract terms", "Save contract terms", "Save plan" (`PrimaryButton`). The person settings dialog has no primary button: each add and delete saves on its own (UI-D4), and its add buttons are `SecondaryButton`s.
2. The consumed fill of `BudgetMeter` (`bg-accent-400 dark:bg-accent-200`, the Phase 3.2 progress-fill rule) and the consumed bars of `PlannedVsConsumedChart` (`--theme-color-chart`).
3. Chargeability bars in `ChargeabilityChart` and positive-margin bars in `ClientMarginChart` (`--theme-color-chart`).
4. The projected (not yet consumed) segment of `BudgetMeter`: a 45° stripe of the same accent fill at 40% opacity (texture is the non-colour cue that separates it from consumed).
5. Inline text links: "Open project", "Go to Settings" (`text-accent-500 dark:text-accent-400`).
6. Active state of the existing Select/Combobox triggers (unchanged component behaviour).

Accent is never used for: status (on track, at risk, over), loss or margin text, KPI values, table text, row highlight of the current month, the planned series, target ticks, the nav item, or any full-width background.

### Status palette (UI-D2)

Status is always icon + text label + colour; colour is never alone (WCAG 1.4.1). These steps were chosen because the fork already uses green/amber/red steps for success and warning (`text-green-700 dark:text-green-400`, `text-amber-700 dark:text-amber-400` in `resources/js/m365`), but the 700 steps measure 4.47 to 4.52:1 on the light hover row (`#EDF3F4`) and sidebar, under 4.5. This phase uses one step darker in light mode.

| Status | Icon (Lucide, 14px) | Light text and icon | Dark text and icon | Measured contrast (light: card / sidebar / hover; dark: content / card / hover / elevated) |
|--------|--------------------|---------------------|--------------------|------------------------------|
| On track | `CircleCheck` | `text-green-800` `#166534` | `dark:text-green-400` `#4ADE80` | 6.92 / 6.42 / 6.36; 9.78 / 8.68 / 7.57 / 8.01 |
| At risk | `TriangleAlert` | `text-amber-800` `#92400E` | `dark:text-amber-400` `#FBBF24` | 6.88 / 6.38 / 6.32; 10.21 / 9.07 / 7.91 / 8.37 |
| Over budget, loss, below target | `OctagonAlert` | `text-red-700` `#B91C1C` | `dark:text-red-400` `#F87171` | 6.28 / 5.82 / 5.77; 6.16 / 5.47 / 4.77 / 5.05 |
| Not started, Closed, No contract, Incomplete data | `CircleDashed` / `Lock` / `Info` | `text-text-secondary` | `text-text-secondary` | Phase 3.2 neutral ladder (9.21 or more) |

Rules: status colours are text and icon only (no filled pill backgrounds). `StatusPill.vue` = icon + 12px/600 label, `inline-flex items-center gap-1`, no border. Dark `red-400` is not allowed on the pressed surface `#3A3A3A` (4.11:1); rows never use `bg-quaternary`.

### Chart colours (validated)

Validator: `node scripts/validate_palette.js "#8B9091,#007C6B" --mode light --surface "#F9FCFD"` and the dark equivalent, run 2026-11-27. The grey "planned" mark fails the categorical chroma floor by design, because it is not a category: it is a **reference mark** (a target), drawn as a dashed outline, never a filled series. Consumed vs planned separation passes CVD (ΔE 9.6 protan light, 31.5 dark) and the normal-vision floor (15.4 light, 35.5 dark). Dark consumed `#00F5D4` sits above the categorical lightness band (0.868); this is accepted because it is a single accent series (the existing `--theme-color-chart` of the Reporting page) beside one neutral reference, not a multi-hue set.

| Mark | Light | Dark | Contrast vs card |
|------|-------|------|------------------|
| Consumed bar / chargeability bar / positive margin bar | `rgb(var(--theme-color-chart))` at 0.85 (Untangle `#007C6B`) | same token (Untangle `#00F5D4`) | 4.97 light, 10.82 dark |
| Planned (reference outline, 2px dashed) and target tick (2px solid) | `--color-text-tertiary` `#565B5C` | `#ABAEAE` | 6.69 light, 6.77 dark |
| Negative margin bar | `text-red-700` hex `#B91C1C` | `#F87171` | 6.28 light, 6.16 dark (content) |
| Gridlines | `--color-border-tertiary` | same | decorative |
| Meter consumed fill vs track (`bg-quaternary`) | step 400 on `#DDE5E6` | step 200 on `#3A3A3A` | 4.01 light, 7.53 dark (1.4.11 graphic object, 3:1) |
| Meter budget tick (`bg-text-primary`) vs card | `#1C1C1C` | `#F9FCFD` | stands 4px outside the track so it is measured against the card: above 12:1 both modes |

Rose `#F24DA0` and Gold `#FFDA6A` (brand chart-only colours) are not introduced: no chart in this phase has more than one categorical series.

## Access and Money Rendering Contract (D-11, D-16)

The frontend never decides who may see money; it renders what the payload contains. These rules make the UI safe even if a flag is wrong.

| Rule | Contract |
|------|----------|
| Nav item | `AppLayout.vue` renders the "Profitability" item (Lucide `TrendingUp`, after "Goals" in the first list) only when the shared prop `profitability.enabled` is true. Its href is `profitability.url` (no Ziggy route). Label from `profitability.labels.nav` |
| Tabs | Rendered from `profitability.views` (subset of `projects`, `clients`, `people`, `settings`) in that order. A view not in the list is not rendered at all (not disabled, not greyed) |
| Default view | The first view in the list; `?view=` query param selects another; an unknown or forbidden value falls back to the first view silently |
| Money keys | A money cell, column, KPI tile or chart is rendered only when the money key is present in the JSON (`'amount_cents' in row`, `'cost_cents' in row`, `'margin_cents' in row`). Absent key = element not rendered. Never render `0`, `—` or a lock icon for an absent money key at the column or KPI level (no hint that money exists) |
| Mixed rows | When some rows in a table carry money and others do not (an AM who is also PM of another client's project), money columns are shown and the rows without money keys render an empty cell with `aria-label="Not available"` and no visible text |
| Role mapping (for tests and copy only) | Owner/Admin: Projects, Clients, People, Settings, money everywhere. Account manager: Projects (own clients, with money) and Clients (own clients). Project manager only: Projects (hours only). Core Manager without assignment, Employee, Placeholder: no nav item, no page (404), no project summary card |
| Project summary card | Rendered on `ProjectShow.vue` only when the summary endpoint answers 200; a 404 renders nothing (no empty card, no error) |
| Edit affordances | "Edit contract terms" only when the payload says `can_edit_terms: true` (AM of the client, Owner, Admin); "Plan months" only when `can_edit_plan: true` (PM of the project, Owner, Admin). Absent buttons, not disabled ones |

## Page: Profitability (`Pages/Profitability.vue` → `ProfitabilityPage.vue`)

### Header

### Shared states (every view)

| State | Rendering |
|-------|-----------|
| First load | Each card shows `LoadingSpinner` centred with 48px vertical padding; KPI tiles show `--` (StatCard default) |
| Refetch (range change, after save) | Previous data stays visible; a 16px `LoadingSpinner` appears next to the toolbar; no layout shift |
| Load error | One `Card` replacing the view body: `CircleAlert` icon, the "Load error" copy, `SecondaryButton` "Try again" that calls `refetch()` |
| Save error | Toast (error) with the "Save error" copy; the dialog stays open with the user's values |

### View: Projects (Owner/Admin, account managers, project managers)

**Toolbar (right):** `Select` "Contract" with options "Active" (default: projects whose current period exists), "Without contract terms" (billable projects in scope with no contract; only for scopes that can edit terms), "Ended" (end date passed or archived), "All". Then, for scopes that can edit terms, `PrimaryButton` with `Plus` icon "Set contract terms".

**KPI strip** (`grid grid-cols-2 lg:grid-cols-4 gap-4`, `StatCard`s), totals over the rows currently listed (current periods only):
1. "Hours sold" — sum of period budgets.
2. "Hours consumed" — sum of consumption to date.
3. "Still to consume" — sum of `max(sold − consumed, 0)`.
4. "Projects at risk" — count of rows with status At risk or Over budget, value followed by the `TriangleAlert` icon in amber when above 0.

Money strip (second row, same grid, only when at least one listed row has money keys; totals over money rows only): "Amount sold", "Cost to date", "Margin to date", "Projected margin". When rows without money are also listed, a caption under the strip: "Money totals cover {n} of {total} projects (the clients you manage)."

### BudgetMeter anatomy (UI-D6)

- Track: `h-2 rounded-full bg-quaternary` (compact variant in tables: `h-1`).
- Scale: the track represents `max(sold, consumed, projected) × 1.0`; when everything is under the hours sold, the track equals the hours sold.
- Consumed fill: from 0, `bg-accent-400 dark:bg-accent-200`, `rounded-full` start.
- Projected segment: from consumed to the remaining-plan projection, the same accent with `opacity-40` and a 45° stripe (`bg-[repeating-linear-gradient(45deg,currentColor_0_2px,transparent_2px_6px)]` on an accent `text-` colour). Omitted when the projection equals consumed or the period is closed.
- Budget tick: 2px x 16px `bg-text-primary` at the hours-sold position, label above it in 12px "Sold {h}" when the track is scaled beyond the hours sold (over case); otherwise the tick sits at the right end without label.
- Over portion: the part of the consumed fill beyond the budget tick switches to the over colour (`bg-red-700 dark:bg-red-400`; 5.06 light / 4.11 dark vs track, above 3:1).
- Semantics: `role="meter"`, `aria-valuemin="0"`, `aria-valuemax="{sold}"`, `aria-valuenow="{consumed}"`, `aria-valuetext="{consumed} h of {sold} h consumed, projected {projected} h, {status}"`.
