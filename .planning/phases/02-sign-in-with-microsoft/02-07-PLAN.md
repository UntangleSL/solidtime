## Phase Goal

**As a** member of the Untangle team, **I want to** sign in to solidtime with my Microsoft 365 account, **so that** I get in with my work identity and Entra MFA while email/password login keeps working for everyone else.

<objective>
Make Microsoft sessions behave correctly and prove tokens never leak. The callback resumes the guest-stored intended URL (desktop app and browser extension authorize through `/oauth/authorize` on the web login), never sets a remember-me cookie, and skips Fortify's TOTP challenge by design (D-06) while recording per sign-in whether Entra reported MFA (`amr_mfa`), as evidence backing that design. A test matrix proves SEC-01: tokens live only in the encrypted columns of `microsoft_accounts` (D-09).

Purpose: AUTH-06 and SEC-01; the MFA evidence line pairs with the 02-09 doc warning and the 02-11 release gate on tenant MFA enforcement (orchestrator directive on D-06).
Output: controller change, optional hardening of the model/DTO, two Feature test classes green in CI.
</objective>

The host has no system PHP or Docker. Shell state does not persist between Bash calls, so start every Bash call that runs PHP, Composer or a CI gate with:


Toolchain check (the `<precondition>` of the first PHP-running task): `test -x "$PHP_BIN" && "$PHP_BIN" -v | grep -q "PHP 8.3" && "$PHP_BIN" "$COMPOSER_PHAR" --version --no-ansi | grep -q "Composer version 2" || { echo "toolchain missing: see 02-RESEARCH Environment"; exit 1; }`. When it prints that line, halt and report it (re-installing a PHP binary needs owner awareness).

PHPUnit runs only in CI ("PHPUnit Tests", Postgres 15/16/17) on every push to `feature/m365-integration`. Paths under `vendor/` named in read_first are installed dependency sources (git-ignored); they are read-only references and are never modified or committed.

Push protocol (same-wave executors push to the same branch): `git pull --rebase origin feature/m365-integration && git push origin HEAD:feature/m365-integration`. If the push is rejected as non-fast-forward, run the same two commands once more; a second rejection or a rebase conflict stops the plan and is reported. `.planning/` writes are orchestrator-owned in sequential mode.

CI wait (no foreground sleep; start with `run_in_background` and continue when it exits):

```bash

```
