## Phase Goal

**As a** team member, **I want to** have recurring meetings come already assigned to the project I used last time, and other meetings come with a good project suggestion learned from my history, **so that** logging meeting time is mostly confirming instead of choosing.

<objective>
Server side of series pre-assignment, end to end (RULE-01, D-01 first layer: series history): the link records the occurrence's series at conversion, the read derives each visible series' assignment from the time entry behind its most recent link, filters it through the core booking rules, and returns it per meeting together with an opaque series key. The resource shape for the whole phase (series_key, series_ignored, assignment, suggestions) is fixed here, so no later plan changes it again.

Purpose: RULE-01 and the latest-wins half of RULE-05 on the server (D-02, D-03, D-05, D-12, D-13, D-17). Ignore/forget (05-06), the confirm mode (05-05) and learned suggestions (05-09) plug into the pieces built here.
Output: one migration (all new link columns of the phase), resolver, bookability filter, value objects, read wiring, PHPUnit coverage. Wave-1 anchor.
</objective>
