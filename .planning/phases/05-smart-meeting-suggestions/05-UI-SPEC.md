## Layout and Interaction Contract

### 0. What the UI receives (advisory field names)

Per meeting in the meetings payload (owner only; impersonation returns none, D-14):
- `preassignment`: `{ project_id, project_name, project_color, client_name|null, task_id|null, task_name|null, tag_ids[], billable, last_converted_on }` or `null`. Present only for an unassigned, non-dismissed occurrence of a series with history whose project is still usable by the user (D-02). If the series' project was archived or the user lost access, it is `null` and the meeting looks plain; a task or tag that no longer exists is dropped from the pre-assignment silently.
- `is_recurring` (has a series key) and `series_ignored` (bool).

Per form open (single or batch), one suggestions request: ranked candidates `{ project_id, project_name, project_color, client_name|null, reason: { kind: 'series'|'domain'|'person'|'organizer'|'subject'|'last_used', count, value } }` (top 3) and whether the top one is confident (D-07). Reason labels are built client-side by `suggestionReason.ts` from `kind`, `count` and `value`.

### 1. Pre-assigned meeting block in the lane (D-02, D-03, RULE-01)

Same block as 3.1 (accent tint, bar, flat, `rounded-sm`, `CalendarDays` time line), plus a **project line** and an aria suffix. Data attribute `data-preassigned` on the block for tests.

Project line: `flex min-w-0 items-center gap-1` → `OutlookProjectDot` + project name (12px 400, `m365-meeting__meta` colour, `truncate`). Client and task are not shown in the block (hover card and panel carry them). `data-testid="outlook-preassigned-line"`.

| Tier (3.1 heights) | Plain meeting (unchanged) | Pre-assigned meeting |
|--------------------|---------------------------|----------------------|
| T1 (< 18px) | subject | dot + subject (one line) |
| T2 (18-31px) | subject (+ inline time from 150px width) | dot + subject (+ inline time from 150px width) |
| T3 (32-45px) | subject, time line | subject (1 line), project line |
| T4 (46-59px) | subject (2 lines), time line | subject (1 line), time line, project line |
| T4 from 60px (week) / T5 (day) | subject (2 lines), time line, organizer in day view | subject (up to 2 lines), time line, project line. Never the organizer line |

Accessible name: the 3.1 label plus `, pre-assigned to :project` (before the selected / dismissed suffixes). Example: "Weekly sync, 10:00 to 10:30, Outlook meeting suggestion, pre-assigned to Acme Website".

No button is nested inside the block (a block is already `role="button"`; nesting interactive controls breaks its semantics). The one-click Confirm lives in the hover card, the panel and the menu.

**Pending confirm** (request running, from any surface): the dot is replaced by a 12px `LoadingSpinner` (in T3+ inside the project line, in T1/T2 before the subject), the block gets `aria-busy="true"` and `cursor-progress`. No opacity change on text. Success: the meeting leaves the lane like any converted meeting (Phase 4 rule, focus to the next meeting of the day, else the previous, else Sync). Failure: block returns to its pre-assigned look, error toast (Copywriting).

States interplay:
- Selected (Phase 4): ring + check badge as before; the project line stays.
- Dismissed (only with "Show dismissed meetings" on): the dismissed variant wins and shows **no** project line; restoring brings it back.
- Series ignored (only with "Show dismissed meetings" on): dismissed variant, eyebrow and aria suffix "series ignored", no project line (section 5).
- Panel open: open ring as before.

### 2. Hover card delta (RULE-01, RULE-05)

1. Eyebrow (12px 400 `text-tertiary`, `flex items-center gap-1`): `Repeat` 12px + "Pre-assigned · Same series".
2. Project line: `OutlookProjectDot` + project name (12px 600 `text-primary`) + " · Client" (12px 400 `text-tertiary`), one line, truncate.
3. Detail line (12px 400 `text-secondary`, truncate), parts joined with " · ", empty parts omitted: task name, "2 Tags" (core tag count copy), "Billable" / "Non-Billable".

Actions row (`mt-4 flex justify-end gap-2`): `SecondaryButton` `Pencil` "Edit" (opens the panel in form mode, prefilled, same channel as Phase 4 `openForm`), then `PrimaryButton` `Check` "Confirm". Test ids `outlook-hover-edit`, `outlook-hover-confirm`.

### 5. Series controls (D-10, D-11, RULE-04, RULE-05)

| Action | Where | Effect in the UI | Feedback |
|--------|-------|------------------|----------|
| Always ignore this series | Menu, panel More actions (recurring meetings) | Optimistic: every occurrence of the series leaves the lane at once (or turns into the faded variant when Show dismissed is on); panel closes; focus follows the Phase 3 Dismiss rule | Toast success, title "Series ignored", message "Its meetings are hidden. Turn on Show dismissed meetings to undo."; announcement "Series ignored" |
| Stop ignoring this series | Menu, panel More actions, only on faded occurrences of an ignored series | Optimistic: the occurrences return to normal (pre-assigned look if the series has history); focus stays on the same block | Announcement "Series no longer ignored" (no toast, same as Restore) |
| Forget this series | Menu, panel More actions (pre-assigned only) | Optimistic: every occurrence loses its project line and becomes a plain block; toolbar count updates; focus stays on the block | Toast success, title "Series forgotten", message "Its meetings are no longer pre-assigned. Your time entries are unchanged."; announcement "Series forgotten" |
| Change a series' assignment | Edit (form) or Phase 4 batch form with another project | After the conversion, the series' other occurrences show the new project (latest wins, D-05) | Series note in the form before submitting (section 6) |

Faded occurrence of an ignored series: exactly the 3.1 dismissed variant (no bar, dotted border, `EyeOff`), eyebrow "Outlook meeting · Series ignored", aria suffix ", series ignored" (instead of ", dismissed"). An occurrence that is both individually dismissed and in an ignored series shows the series wording and offers both "Restore meeting" and "Stop ignoring this series".

Failure of any series action: optimistic change reverts, toast error "Could not update this series" / "Try again in a moment." (existing `retry_body`).

No confirmation dialogs: nothing here touches time entries (D-12) and each action has an undo path (Stop ignoring; Forget is undone by the next conversion). No separate rules manager page (D-11) **(default)**.

"Show dismissed meetings" setting: same switch, help text updated to mention ignored series (Copywriting).

### 6. Single mini form delta (D-03, D-05, D-07, RULE-01, RULE-03)

Layout unchanged except under the project picker, inside the same `Field` group:

1. **Reason line** (`mt-1 flex min-w-0 items-center gap-1`, 12px 400 `text-tertiary`, icon 12px, text truncates, full text in `title`), `data-testid="outlook-suggestion-reason"`:

| Prefill source | Icon | Copy |
|----------------|------|------|
| Series pre-assignment | `Repeat` | "Same series" |
| Suggestion, attendee domain | `AtSign` | "Like 4 meetings with @client.com" (singular: "Like 1 meeting with @client.com") |
| Suggestion, person (attendee) | `Users` | "Like 4 meetings with Ana López" |
| Suggestion, organizer | `User` | "Like 4 meetings organized by Ana López" |
| Suggestion, subject words | `TextSearch` | "Like 4 meetings with a similar subject" |
| Phase 4 fallback (last used / latest entry) | `Clock` | "Last used" |
| Nothing to prefill | none | line not rendered |

   The line describes the project currently in the picker: after a quick pick it shows that candidate's reason; after a manual pick in the picker that is not a candidate it disappears.

2. **Quick picks** (`OutlookSuggestionPicks`, `mt-2 flex flex-wrap gap-2`, `role="group"`, `aria-label` "Other suggestions"): up to 2 chips for the highest-ranked candidates that are not the current project. Chip = outline `Button size="sm"`, content `OutlookProjectDot` + label `max-w-40 truncate` "Project · Client" (client omitted when none), `aria-label` "Use Acme Website (Acme)", `title` = the candidate's reason. Click: sets the project (task cleared, billable follows the project's default, tags kept), focus moves to the Create button. No chips when there are no other candidates. `data-testid="outlook-suggestion-pick"`.

3. **Series note** (`mt-2 flex items-start gap-1`, 12px 400 `text-tertiary`, `Repeat` 12px), `data-testid="outlook-series-note"`:
   - Recurring meeting, not pre-assigned, a project chosen: "Other meetings in this series will come pre-assigned to this project."
   - Pre-assigned meeting, project changed away from the pre-assignment: "This series will use the new project from now on. Entries already created stay as they are."
   - Otherwise: not rendered.

Prefill order (D-02, D-07): (1) series pre-assignment: project, task, tags, billable all prefilled; (2) top suggestion when the server marks it confident: project only (billable follows the project, task empty, tags empty); (3) the Phase 4 rule (last project used for a conversion, else latest entry's project) with "Last used". Below-threshold candidates still appear as quick picks under the fallback. Description and times stay the meeting's own (Phase 4).

Loading: the suggestions request starts when the form mounts. Prefill (3) appears at once; if (1) or (2) arrives later and the user has not touched the project, it replaces the prefill (same "late prefill never overrides the user" rule as Phase 4). If the lookup takes longer than 300ms the reason line shows a 12px `LoadingSpinner` + "Checking your history…"; if it fails, silently keep (3). Pre-assignment data is already in the meeting payload, so (1) never waits.

Focus rule unchanged (Create button when a project is prefilled, else the picker). Submit, validation, errors unchanged. Submitting a pre-assigned meeting through Edit is the normal Phase 4 conversion with the edited values.

### 7. Batch mini form delta (D-08)

Same additions as the single form, computed across the selected meetings:
- Prefill: if every selected meeting is pre-assigned to the same project, prefill project, task, tags, billable from it with reason "Same series". Otherwise the project that is the top candidate (pre-assignment counts as top) for the most selected meetings, with reason "Suggested for 2 of 3 meetings" (`Users` icon); ties go to the higher-ranked overall score; if no meeting has a candidate, the Phase 4 rule with "Last used".
- Quick picks: the next 2 most common top candidates.
- Series note: when at least one selected meeting is recurring: "Recurring meetings here will use this project for their series from now on."

The per-meeting result list, retry and toasts are unchanged.
