## Phase Goal

**As a** team member, **I want to** have recurring meetings come already assigned to the project I used last time, and other meetings come with a good project suggestion learned from my history, **so that** logging meeting time is mostly confirming instead of choosing.

<objective>
The learned engine as pure PHP (D-01 second layer, D-06): a subject tokenizer with Spanish and English stop words, the meeting feature extractor and keyed hashing of the stored signals, and an explainable scorer that ranks projects with a reason and a confidence rule. No database, no framework state, no external service: every case is a local PHPUnit unit test.

Purpose: RULE-03's ranking core. 05-05 stores `MeetingSignals::hashed()` on each new link; 05-09 feeds the user's history and a target meeting into `ProjectSuggestionEngine::rank()` inside the read.
Output: five classes in `App\Microsoft365\Suggestions`, three unit test classes (Gate U runs them locally).
</objective>

- `MeetingSignals::hash(string $kind, string $value, string $secret): string` with kinds `person` (any address: organizer or attendee, so the same person matches in either role), `domain`, `token`; 16 lower-hex characters of `hash_hmac('sha256', $kind.'|'.$value, $secret)`.
- `ProjectSuggestionEngine::rank(array $target, array $labels, list<array{project_id: string, age_days: float, series: ?string, forgotten: bool, signals: array}> $history, ?string $excludeSeries = null, int $limit = 3): list<Suggestion>` where `$target` is the hashed payload of the target meeting (same secret) and `$labels` maps a target hash => readable value for the reason (person hash => display name or null, domain hash => bare domain). Rows with `series === $excludeSeries && forgotten` are skipped.
- `Suggestion` (final readonly): projectId, score (float, server only), confident (bool), reason (Reason); `toArray(): array{project_id: string, confident: bool, reason: array{kind: string, count: int, value: ?string}}` (no score; 05-09 merges the project display fields).
- `Reason` (final readonly): kind ('domain'|'person'|'organizer'|'subject'), count (int), value (?string); `toArray()`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Meeting data (other people's addresses, subjects) -> stored link signals | Personal data must not outlive the meeting cache in readable form |
| Engine output -> browser | Reasons carry readable values taken from the user's own current meeting |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-06 | Information disclosure | MeetingSignals::hashed (stored on links) | high | mitigate | HMAC-SHA256 keyed with the app secret, kind-prefixed, 64-bit truncation; plain sha256 of an email would be dictionary-reversible; test asserts no '@', domain or token text in the payload |
| T-05-07 | Information disclosure | Reason value | medium | mitigate | Reason values are display names or bare domains of the target meeting only, never a full address (person without a name falls back to the domain); no score leaves the server (toArray omits it) |
| T-05-08 | Denial of service | rank() over large history | low | mitigate | Linear in history rows x target features (target features capped: 12 tokens, broadcast guard over 25 attendees); 05-09 caps history at 2000 rows / 365 days |
| T-05-SC | Tampering | npm/pip/cargo/Composer installs | high | mitigate | No package installs (hand-written stop-word list instead of a package, RESEARCH alternatives) |
</threat_model>
