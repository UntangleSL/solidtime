## Phase Goal

**As a** team member, **I want to** have recurring meetings come already assigned to the project I used last time, and other meetings come with a good project suggestion learned from my history, **so that** logging meeting time is mostly confirming instead of choosing.

<objective>
Learned suggestions in the calendar read: load the user's labelled history once, rank every meeting that has no series assignment with the pure engine, and return the top three with display names and a reason. Then prove the forget/ignore interplay end to end now that the confirm mode (05-05) and the series settings (05-06) both exist.

Purpose: RULE-03 server side (D-06, D-07 confidence, D-09), RULE-05 forget lifecycle (D-11), D-12, D-14.
Output: history loader, per-read suggester, read wiring, feature tests. Wave-3 anchor.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Links of all users -> one user's read | The history table holds every user's learning data |
| Server ranking -> browser | Only names, a bare domain and a count leave the server |
| Read endpoint -> database load | Scoring runs inside a throttled read |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-30 | Information disclosure | SuggestionHistory query | high | mitigate | `l.user_id` = session user, `te.user_id = l.user_id`, `te.organization_id` = current organization; test that another user's links never change the ranking |
| T-05-31 | Information disclosure | suggestion payload | high | mitigate | Suggestion::toArray omits the score; reason values are display names or bare domains of the user's own meeting; test asserts no email-shaped string, no attendee keys |

| T-05-34 | Denial of service | scoring per read | medium | mitigate | One history query (limit 2000, 365 days) and one bookable query per read, constant query count test, read throttle 60/min |
