## Toolchain, push protocol and CI gates (identical in every 03.1 plan)

Adapted from Phase 3 (03-01, 03-07). The host has no Postgres and no system PHP: PHPUnit and Playwright run only in GitHub CI, on every push to `feature/m365-integration` (no local app server, so specs are compiled and listed locally and executed in CI). Shell state does not persist between Bash calls; start every Bash call that runs a CI wait or a CI gate with:

```bash
export PHP_TOOLCHAIN_DIR="${PHP_TOOLCHAIN_DIR:-C:/Users/JuanHerrero/.local/solidtime-php-toolchain}"
export M365_LOG_DIR="$PHP_TOOLCHAIN_DIR/ci-logs" && mkdir -p "$M365_LOG_DIR"
```

Repository rules (`.claude/CLAUDE.md`, D-09): this plan edits one fork-owned spec (already in the ledger's fork-owned table); stage with explicit `git add <paths>` (never `-A` or `.`); hooks stay on; commit trailer exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never read `.env*` files and never print secrets; `.planning/` writes are orchestrator-owned; no package installs (run `npm ci` once in a fresh worktree whose `node_modules` is missing, never commit it). Specs need no Microsoft credentials: the CI environment has the integration off and meetings are injected through `window.__TEST_SET_OUTLOOK_MEETINGS__`.

Parallel waves (owner, 2026-11-10): plans of one wave have disjoint `files_modified` and may run at the same time in separate worktrees. Never edit a file owned by another plan; a Playwright failure in a spec owned by another plan is reported (test name, error, run URL), not fixed here.

Push protocol (once per plan, in its last task): `git pull --rebase origin feature/m365-integration && git push origin HEAD:feature/m365-integration`. On a non-fast-forward rejection run both commands once more; a second rejection or a rebase conflict stops the plan and is reported.

CI batching (owner): this is the one implementation plan that waits for Playwright (its only deliverable is browser tests, and it is the phase's single pre-release browser checkpoint); the full ten-workflow gate stays with the release (03.1-08).

- **CI wait (start with `run_in_background`, never a foreground sleep; Playwright runs 8 shards, up to 60 min):**

```bash
SHA=$(git rev-parse HEAD); until [ "$(gh run list --commit "$SHA" --limit 40 --json workflowName,status --jq '[.[] | select(.workflowName=="NPM Test Unit" or .workflowName=="NPM Lint" or .workflowName=="NPM Typecheck" or .workflowName=="NPM Format Check" or .workflowName=="NPM Build" or .workflowName=="Playwright Tests")] | (length==6 and all(.status=="completed"))')" = "true" ]; do sleep 60; done
```

- **Gate W+E:** prints exactly `NPM Build=success;NPM Format Check=success;NPM Lint=success;NPM Test Unit=success;NPM Typecheck=success;Playwright Tests=success` (command in Task 2). On a red Playwright run read the failures with `gh run view <id> --log-failed` and the merged report artifact.
