## Shell setup, push protocol and gates

Start every Bash call that runs a CI gate or writes a log with:

```bash
export PHP_TOOLCHAIN_DIR="${PHP_TOOLCHAIN_DIR:-C:/Users/JuanHerrero/.local/solidtime-php-toolchain}"
export M365_LOG_DIR="$PHP_TOOLCHAIN_DIR/ci-logs" && mkdir -p "$M365_LOG_DIR"
```

This plan runs no PHP locally (only `gh`, `curl`, `git`, `node` and the docs gates). Push protocol: `git pull --rebase origin feature/m365-integration && git push origin HEAD:feature/m365-integration` (retry once on a non-fast-forward rejection; a second rejection or a conflict stops and is reported); stage with explicit `git add <paths>`, hooks on, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never read `.env*` files and never print secrets. Dokploy is changed ONLY by the orchestrator via MCP after explicit owner approval; the executor never sees or handles secret values. Images are pinned by `sha-<7>` tag because Dokploy does not re-pull a reused tag (02-11 key decision). Phase 3.2 may be planned or executed on the same branch in parallel: never edit 03.2 files, and surface any 03.2 code commit that would ship with R to the owner.
