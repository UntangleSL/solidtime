# Phase 3.1 Plan 04: Meeting context menu and lane captions Summary

A right-click on a meeting block now opens a meeting menu through one additive core slot. The menu shows the subject, "Open in Outlook" (safe https only, `noopener,noreferrer`) and Dismiss/Restore, and focus moves the same way the panel moves it. Day headers get a "My time | Outlook" caption row while the Outlook cluster is active.

## What was built

- **Core overlay branch** (`useContextMenu.ts`): `contextMenuOverlayElement`. If the target has no `[data-event-id]` ancestor but has a `[data-calendar-overlay]` one, the block is stored and the click time is still computed, so the default items keep working when no fork slot exists. The entry branch and the empty-slot branch reset it. A menu opened from the keyboard on a focused block takes the same branch.
- **Core slots** (`TimeEntryCalendar.vue`):
  - `context-menu-overlay` (`{ element }`) is the first `ContextMenuContent` branch. It renders only when the element is set and the slot is provided; otherwise the upstream menus are unchanged.
  - The `day-overlay` slot now also passes `contextMenuOpen` and `interacting` (`isDragging || isResizing || isSelecting`).
  - Each header cell has a `day-header-extra` slot (`{ dayStr, isDayView }`).
- **Page wiring** (`Calendar.vue`): the `#context-menu-overlay` and `#day-header-extra` templates render only when the Outlook labels exist.
- **`OutlookMeetingContextItems.vue`** (fork):
  - Looks up the meeting by `data-ghost-id` in the current list when it renders. A stale element shows only the "(No subject)" label and no actions (T-03.1-08).
  - The subject is rendered through text interpolation only (T-03.1-10).
  - "Open in Outlook" appears only when `safeHttpsUrl` returns a URL, and opens it with `window.open(url, '_blank', 'noopener,noreferrer')` (T-03.1-07).
  - A separator plus Dismiss (EyeOff) or Restore (Eye) appears only when `canAct` is true.
  - After Dismiss, focus goes to the next block of the same day, else the previous block, else the Sync button. When dismissed meetings are shown it stays on the same block. After Restore it stays on the same block.
  - Nothing in the menu touches time entries (T-03.1-09).
- **`OutlookLaneCaption.vue`** (fork):
  - An `aria-hidden` row, `h-4` and `-mx-2`, that renders only for `connected` or `reconnect`.
  - "My time" uses `flex-1`. The Outlook segment's width is the `dayOverlayLane` string, with a `border-l border-border-tertiary` and a 12px `CalendarDays` icon in `text-accent-600 dark:text-accent-400`.
  - On days without a lane the row is empty but keeps its height.
- **Ledger**: new rows for `useContextMenu.ts` and `useContextMenu.test.ts`. The `TimeEntryCalendar.vue` and `Calendar.vue` rows are extended, and the fork calendar path description is updated.

## Deviations from Plan

1. **[Orchestrator rule] No push, no CI wait, no Gate W.** The executor rules say "Do NOT push", which overrides the plan's push protocol in Task 3. The fast CI gate (Gate W) has to run after the orchestrator pushes.
2. **[Ordering] Focus rules were written in Task 1.** `OutlookMeetingContextItems.vue` got its focus logic in the Task 1 commit. Task 3 added only the focus tests.
3. **[Rule 1 - robustness] Wait for the menu to close before moving focus.** The plan says nextTick plus a zero-delay timeout. Reka returns focus in a zero-delay timeout that it registers only when the content unmounts. In the browser that happens after the close animation, so it would run after ours and could pull focus back. The component therefore waits until the menu element is out of the DOM (MutationObserver, 1 s fallback) and then runs the zero-delay timeout.
4. **[Rule 1] Focus targets are looked up in the captured lane group.** A meeting that spans several days has one block per day with the same `data-ghost-id`. If the group is gone, the lookup falls back to `document`.
5. **[Test detail] Lane width in the caption test.** happy-dom drops `min()`/`max()` widths, so the test uses a `calc()` stand-in for the faked `dayOverlayLane` string. The day-view case still checks the real arguments.
