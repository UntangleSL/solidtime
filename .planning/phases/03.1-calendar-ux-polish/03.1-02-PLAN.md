## Toolchain, push protocol and CI gates (identical in every 03.1 plan)

Adapted from Phase 3 (03-01, 03-07). The host has no Postgres and no system PHP: PHPUnit and Playwright run only in GitHub CI, on every push to `feature/m365-integration`. A portable PHP 8.3 toolchain runs Pint locally, only in plans that touch PHP (this one does). Shell state does not persist between Bash calls; start every Bash call that runs PHP, a CI wait or a CI gate with:

```bash
export PHP_TOOLCHAIN_DIR="${PHP_TOOLCHAIN_DIR:-C:/Users/JuanHerrero/.local/solidtime-php-toolchain}"
export PHP_BIN="$PHP_TOOLCHAIN_DIR/phprun/php.exe"
export M365_LOG_DIR="$PHP_TOOLCHAIN_DIR/ci-logs" && mkdir -p "$M365_LOG_DIR"
```

Toolchain check (precondition of Task 3): `test -x "$PHP_BIN" && "$PHP_BIN" -v | grep -q "PHP 8.3" && test -f vendor/bin/pint || { echo "toolchain missing: see 02-RESEARCH Environment"; exit 1; }`. In a fresh worktree without `vendor/`, copy the main tree's gitignored `vendor/` into it first (directory junctions are blocked by the sandbox, 03-11 precedent); never commit it.

Repository rules (`.claude/CLAUDE.md`, D-09): fork code only in `resources/js/m365/` (and `app/Microsoft365/`); core edits minimal and additive; every core file a plan touches gets its row in `docs/m365/TOUCHED-CORE-FILES.md` within the same plan (this plan touches no core file: lang/*/microsoft365.php are already ledgered as new files in core directories); Vue `<script setup lang="ts">`, theme tokens, no raw colours, no `v-html`, no `console.log`, no `@ts-ignore` / `eslint-disable`; stage with explicit `git add <paths>` (never `-A` or `.`); hooks stay on; commit trailer exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never read `.env*` files and never print secrets; `.planning/` writes are orchestrator-owned; no package installs or upgrades (run `npm ci` once in a fresh worktree whose `node_modules` is missing, never commit it).

Parallel waves (owner, 2026-11-10): plans of one wave have disjoint `files_modified` and may run at the same time in separate worktrees. Never edit a file owned by a same-wave sibling plan (here: `useOutlookMeetings.test.ts` belongs to 03.1-03); if one of its tests breaks because of this plan, report it instead.

Push protocol (once per plan, in its last task): `git pull --rebase origin feature/m365-integration && git push origin HEAD:feature/m365-integration`. On a non-fast-forward rejection run both commands once more; a second rejection or a rebase conflict stops the plan and is reported.

CI batching (owner): each plan runs the local gates, pushes, then waits in the background for the fast workflows on its own HEAD. This plan touches PHP, so its wait also covers the three PHP workflows. Playwright is NOT awaited here (03.1-07 and the release 03.1-08 check it).
