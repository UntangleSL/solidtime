# Phase 3.1 Plan 03: Solid Outlook meeting blocks in a split "My time / Outlook" lane Summary

Meetings now render as solid, accent-tinted blocks with a 3px bar and 12px text in a stable, washed Outlook lane on the right half of each day that has meetings. The number of side-by-side columns follows the measured lane width (56px per column). Overlaps beyond that cascade in 8px steps. Every colour comes from the Phase 3.2 `--m365-*` properties, with the UI-SPEC formulas as fallback.

## What was built

- **Lane geometry (`ghostLayout.ts`)**: new D-04 lane strings. `maxGhostColumns` is floor(width / 56) clamped to 1..3 (week) or 1..4 (day), and an unusable width gives 1. `layoutGhostsForDay` takes an optional `maxColumns` (default 3). Extras share the last column with `cascade` 1, 2, 3 and then stay at 3, and the cascade restarts once that column is free again. `ghostColumnStyle` builds equal columns inside 2px gutters with 2px gaps and shifts each cascade step 8px right. `ghostBlockWidthPx` gives the same width in pixels.
- **Layer (`OutlookGhostLayer.vue`)**:
  - The lane carries `data-testid="outlook-lane"`, `.m365-lane`, the 6% wash (8% in dark), a 1px `--color-border-tertiary` left divider and `pointer-events-none`.
  - Blocks are `.m365-ghost.m365-meeting`: opaque tinted fill, 1px tinted border, 3px bar, `rounded-sm`, no shadow, a hover fill and `hover:z-[1]` / `focus:z-[1]`.
  - The focus-visible ring is unchanged. The panel ring now comes from `data-panel-open` (`ring-accent-700`, `dark:ring-accent-200`).
  - A 1px gap under each block (height minus 1). Text is 12px with 14px leading.
  - Content tiers by height: under 18px, 18-31px, 32-45px, from 46px, and from 60px in day view (organizer line with the `User` icon).
  - The time line shows `CalendarDays` and the time range, plus a right-aligned `Video` for online meetings. The T2 inline start-end appears from 150px of block width; under 96px the time line shows the start time only.
  - Dismissed variant `.m365-meeting--dismissed`: no bar, 1px dotted text-tertiary border, 6% fill, weight-400 secondary subject, `EyeOff` icon, aria-label suffix kept.
  - The lane width is measured with `useResizeObserver`. Until the first measurement the column cap applies.
- **Tests**:
  - Vitest m365 + FullCalendar: 174 tests, all passing.
  - New tests cover the lane strings, `maxGhostColumns` examples, cascade sequences (5 -> 1,2,3; 7 -> 1,2,3,3,3), back-to-back meetings, `ghostColumnStyle` for 1..4 lanes and cascade 0..3, every content tier, Video and organizer variants, the dismissed variant and the `data-panel-open` ring.
  - The layer was also tested with a stubbed ResizeObserver at 113 / 88 / 420px, plus the 150px and 96px width rules and DOM (Tab) order.
  - `useOutlookMeetings.test.ts`: only the two lane assertions changed, now via `ghostLaneWidth()`.
- **Playwright (`e2e/outlook-meeting-look.spec.ts`)**:
  - Sky-blue project entry vs meeting in light and dark: disjoint zones, opaque meeting fill different from the entry, `border-left-width` 3px, meeting `box-shadow` none vs a shadowed entry, subject contrast at least 4.5.
  - Six overlapping meetings at 1366x900 week, 1800x1000 week and 1500x900 day: distinct non-cascaded left edges equal the expected column count, Tab reaches all six in start order, and every block with a unique position hit-tests.
  - Screenshots and the measured lane widths are attached as artifacts and annotations.
  - The colour parser reads `rgb()/rgba()` and `color(srgb ...)`, and converts anything else (the dark `oklch()` tokens) through a 1px canvas.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Dark fallback selector would have styled `:root`**
- **Found during:** Task 1
- **Issue:** The plan says to use `:global(:root.dark)` to pick the dark fallback. In `@vue/compiler-sfc`, a `:global(...)` anywhere in a selector replaces the whole selector with its argument. So `:global(:root.dark) .m365-meeting` compiles to `:root.dark`, which would set the meeting fill on the page root.
- **Fix:** Used `:root.dark .m365-meeting`. Vue scopes only the last compound, so `:root.dark` stays global. The same applies to `.m365-lane`.
- **Files modified:** `resources/js/m365/calendar/OutlookGhostLayer.vue`
- **Commit:** 1a8847ac

**2. [Rule 3 - Blocking] Prettier wraps long `var(--m365-*, <formula>)` so the property name starts a line**
- **Issue:** The full UI-SPEC formula inside each `var()` goes past 100 characters. Prettier then breaks it so that `--m365-meeting-bg,` starts a line, which fails the plan's "no declaration" grep (`^\s*--m365-(meeting|lane)` must be 0). It would also look like a declaration to the Phase 3.2 drift guard.
- **Fix:** The formulas live in local `--fb-*` properties: light on `.m365-meeting` / `.m365-lane`, dark redefined under `:root.dark`. Each `--m365-*` is consumed on one line as `var(--m365-x, var(--fb-x))`. Values are identical to the UI-SPEC, and no `--m365-*` property is declared.
- **Commit:** 1a8847ac

**3. [Rule 3 - Blocking] happy-dom drops `calc()` with nested parentheses**
- **Issue:** The direct formula `calc((100% - Rpx) * k / n + o)` disappears from inline styles in happy-dom, so the column positions could not be asserted.
- **Fix:** `ghostColumnStyle` expands it to flat `calc(<pct>% + <px>px)` strings. Examples: `calc(50% + 1px)`, `calc(33.3333% - 2.6667px)`. The geometry is the same.
- **Commit:** a5078dfa

**4. Execution rules over plan text: no push, no CI wait**
- The plan's Task 3 pushes to `feature/m365-integration` and waits for Gate W. The orchestrator's exec rules forbid pushing (the orchestrator merges this worktree branch), so neither step was run. Gate W (the five fast NPM workflows) and the Playwright run need to happen after the merge.
