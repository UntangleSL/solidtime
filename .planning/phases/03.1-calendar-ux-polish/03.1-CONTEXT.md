# Phase 3.1: Calendar UX Polish - Context

**Gathered:** 2026-11-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Make the solidtime calendar easier to read and navigate, using the owner's Phase 3 UAT feedback and Clockify's calendar as the reference. In scope: weekend visibility, readable high-contrast Outlook meeting blocks with a clear visual separation between "Outlook calendar" and "time entries", a desktop hover tooltip on meetings, context-menu layering, mouse wheel / trackpad scroll and zoom, and a visible Sync cooldown.

Requirements: UX-01..UX-06.

Not in this phase: creating a time entry from a meeting (Phase 4, ASGN-01, which will place that action in this phase's tooltip and panel), themes / accent colour / branding / organization icon (Phase 3.2), series rules (Phase 5).

</domain>

<decisions>
## Implementation Decisions

### Existing settings (found in code, not to rebuild)
- **D-01:** Start hour, end hour, snap interval and "Grid Scale" (slot minutes) already exist in `CalendarSettingsPopover.vue` / `calendarSettings.ts`, persisted in localStorage `solidtime:calendar-settings`. UX-01 adds only "show weekends" (default: shown, as today; superseded by D-owner-UAT: hidden) to that same popover and storage, through the existing `mergeDefaults` object. Persistence stays per browser (localStorage), like the existing settings.

- **D-owner-UAT:** Weekends hidden by default (owner, 2026-11-17, after the Phase 3.1 UAT: "que por defecto no enseñe weekends"). The "Show weekends" switch still turns them on per browser. `DEFAULT_CALENDAR_SETTINGS.showWeekends` is `false` and a missing or non-boolean stored value means hidden. Because `useLocalStorage` had already written the old default (`showWeekends: true`) into every browser that opened the calendar, a one-time migration (`migrateWeekendsHiddenDefault`, guarded by localStorage `solidtime:calendar-weekends-hidden-default`) resets that stored `true` to `false` once; any choice made afterwards sticks.

### Meeting block look (owner, 2026-11-16)
- **D-02:** Outlook meeting blocks use a **solid fill** (Clockify-like): a light, opaque background with dark, readable text in light theme (and the dark-theme equivalent), plus a coloured side bar or equivalent marker so they stay clearly distinct from time entries, which keep their project colour. Replaces the Phase 3 dashed, translucent ghost (Phase 3 D-06 wording "outlined / hatched / translucent" is superseded; "visually distinct, never counted in totals" still holds).
- **D-03:** Show more of the meeting: subject on up to two lines when height allows, time range, Teams icon; truncation only when space truly runs out. Dismissed meetings keep a distinct, quieter variant.

### Width and calendar-vs-entries separation (owner delegated to a UX pass, 2026-11-16)
- **D-04:** The owner worries that full-width meetings could be hard to interpret. The UI researcher (gsd-ui-phase) must design the layout so that at a glance a user sees (a) the key meeting information and (b) which side is "Outlook calendar" and which is "my time entries". Full width when no time entry overlaps is allowed only if that separation stays obvious; otherwise keep a lane, possibly wider than today's 30%. The UI-SPEC must state the chosen rule with a short rationale and the alternatives considered. Non-negotiable from Phase 3: a meeting overlapping a time entry never hides it or is hidden by it (Phase 3 D-01, D-23), entries stay draggable/resizable, ghosts never start a slot selection (CAL-02).

### Hover tooltip (UX-03)
- **D-05:** On pointer devices with hover, resting on a meeting shows a tooltip with its details (subject, time, organizer, Teams/online, dismissed state) after a short delay. Click still opens the existing detail panel (03-09). Touch devices keep click only. Built so Phase 4 can add "Create time entry / Assign to project" inside it (keep it extendable like the panel's slots).

### Context menu layering (UX-04)
- **D-06:** Opening the right-click context menu closes any open meeting tooltip or panel; the menu must never render underneath them. Right-click on a meeting should not silently open the empty-slot menu (03-05 carry-over): either a meeting-specific menu (Dismiss, Open in Outlook; Phase 4 adds create entry) or the same actions as the panel. Exact menu items are Claude's discretion.

### Wheel / trackpad navigation (UX-05)
- **D-07:** Plain wheel / two-finger scroll keeps scrolling through the hours. Ctrl/Cmd + wheel and trackpad pinch zoom the hour height (in steps, persisted with the other settings, with sensible min/max), keeping the time under the pointer anchored. Today the only zoom is "Grid Scale"; how zoom maps onto `SLOT_HEIGHT` / slot minutes is Claude's discretion as long as drag, resize and slot selection snap correctly at every zoom level.

### Sync cooldown (UX-06)
- **D-08:** After a manual "Sync Outlook" the user sees that the button is cooling down and when it is available again (e.g. a short countdown or progress ring, plus tooltip text). Automatic syncs triggered by week navigation must not keep the manual button disabled; only manual syncs and server back-off (retry_after) start the visible cooldown. Server-side throttles and the minimum interval from Phase 3 stay unchanged.

### Carried forward
- **D-09:** Fork isolation: changes to core calendar files are minimal, additive and ledgered in `docs/m365/TOUCHED-CORE-FILES.md`; fork UI in `resources/js/m365/`. UI strings in English with the lang/es mirror pattern from Phase 3 where fork copy exists.
- **D-10:** Testing (owner, 2026-11-10): every behaviour ships with automated tests that run in GitHub CI (Vitest; Playwright for pointer, wheel and layering behaviour). Batch CI waits per pair of plans and keep Playwright for the release gate when possible; plans that touch independent files should be put in the same wave so they can run in parallel.

### Claude's Discretion
- Tooltip delay, zoom steps and limits, countdown visual, exact colours within the theme tokens (Phase 3.2 will rework the palette; use tokens, not raw colours), context-menu item set.

</decisions>
