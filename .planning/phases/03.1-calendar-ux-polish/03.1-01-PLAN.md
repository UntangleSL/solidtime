## Phase Goal

**As a** team member, **I want** a calendar that is easier to read and move around (view options, readable meeting blocks, hover details, smooth zoom and scroll), **so that** working with time entries and Outlook meetings feels as fluid as in Clockify.

<objective>
UX-01: a persistent "Show weekends" view option in the existing calendar settings popover (03.1-UI-SPEC section 5, CONTEXT D-01), plus one sanitised settings shape that every later 03.1 plan builds on (03.1-RESEARCH Pitfall 8). Start/end hour, snap and Grid Scale already exist (D-01) and are not rebuilt; they gain input validation on read.

Purpose: users who never work weekends get five wider columns (which also widens the Outlook lane of 03.1-03), and a corrupted localStorage value can no longer break the grid.
Output: settings type + sanitiser, weekend filter in the navigation composable, popover row with a package-local Switch, Vitest and Playwright proof, ledger rows.
</objective>

Parallel waves (owner, 2026-11-10): plans of one wave have disjoint `files_modified` and may run at the same time in separate worktrees. Never edit a file owned by a same-wave sibling plan; if one of its tests breaks because of this plan, report it instead.

Push protocol (once per plan, in its last task): `git pull --rebase origin feature/m365-integration && git push origin HEAD:feature/m365-integration`. On a non-fast-forward rejection run both commands once more; a second rejection or a rebase conflict stops the plan and is reported.

CI batching (owner): each plan runs the local gates, pushes, then waits in the background for the fast workflows on its own HEAD (Gate W). Same-wave plans wait at the same time, so a wave costs one CI cycle. Playwright is NOT awaited here; its run for this push is covered by 03.1-07 and by the release gate (03.1-08).
