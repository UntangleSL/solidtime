## Brand Rules: adopted, adapted, not adopted

Source: `untangle-brand` and `untangle-design` skills. The brand targets decks and landing pages; solidtime is a dense data tool, so some rules are adapted. Each row is a locked decision of this contract.

| Brand rule | Decision | Rationale |
|-----------|----------|-----------|
| Only `#1C1C1C` dark and `#F9FCFD` light; never pure black or white | Adopted for every new surface and text value. New markup never uses `text-white`, `bg-white` or `#fff`/`#000` | Brand hard rule 1 |
| Teal `#00F5D4` is the protagonist accent, never a full background | Adopted. Teal is the default accent (preset "Untangle"). It fills only small controls (buttons, timer button, organization letter tile), never a page, card or sidebar | Brand hard rule 2 |
| Rose `#F24DA0` and Gold `#FFDA6A` only in charts | Adopted. Neither is an accent preset, and no hue near them is offered (no pink, no yellow). They stay reserved for a future multi-series chart palette; this phase does not introduce them | Brand hard rule 4 |
| Light text-teal is `#007C6B` (4.97:1 on `#F9FCFD`) | Adopted: it is light-mode accent step 400 of the Untangle preset | Brand `colors_and_type.css` `--accent` on `.on-light` |
| 70% dark / 30% light | Adapted: the mode follows the system (D-02); both modes are fully branded. No forced dark | Owner decision D-02 |
| One family, Syne | Adapted: Syne only for page titles; Inter for everything dense | See Typography |
| Radius 0, glass blocks, substrate circles and grid | Not adopted. `--radius: 0.5rem` stays; no glass, no decorative circles | Colour-only re-skin (BRAND-01); glass and blur cost legibility and performance in tables and the calendar. Brand allows the opaque card fallback for dense content |
| Borders over drop shadows | Adopted for new elements (no new shadows). Existing `shadow-card` and `shadow-dropdown` stay | Minimal churn |
| Logo replacement (solidtime mark to Untangle wordmark) | Not in scope. The product mark is unchanged; only the organization icon is new | Not requested |

## Spacing Scale

Declared values (multiples of 4, Tailwind units in parentheses):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`1`) | Gap between icon and text inside a button, check icon inset |
| sm | 8px (`2`) | Gap between the icon preview and its buttons, gap between helper text and control |
| md | 16px (`4`) | Not used by new markup (the description sits 8px under the swatch row, `mt-2`) |
| lg | 24px (`6`) | Existing FormSection grid gap (`gap-6`), unchanged |
| xl | 32px (`8`) | Swatch diameter (`h-8 w-8`) |
| 2xl | 48px (`12`) | Not used by new markup |
| 3xl | 64px (`16`) | Not used by new markup |

Exceptions:
- Swatch row gap is 12px (`gap-3`); a swatch cell is 32px with a 2px ring and a 2px ring offset when selected (the ring is outside the 32px box and is not a spacing value).
- Organization icon tile sizes: 20px (`h-5 w-5`, switcher trigger and list rows, the existing letter-tile size) and 80px (`h-20 w-20`, settings preview, same as the profile photo). Both are multiples of 4.
- Touch target: a swatch is 32px, above the WCAG 2.5.8 minimum of 24px; the whole swatch is the hit area, with a 12px gap so neighbours cannot be mis-hit.

## Typography

Exactly four sizes and two weights are declared for new markup. Sizes are the existing theme sizes (`tailwind.theme.js`); line heights are the existing theme line heights (no override).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 15px (`text-base`) | 400 | 22px (1.47) |
| Label and helper | 13px (`text-sm`) | 400 | 18px (1.38) |
| Caption (status text; the initial in the 20px tile uses 600) | 12px (`text-xs`) | 400 | 16px (1.33) |
| Heading (page title in Syne; the initial in the 80px tile in Inter) | 20px (`text-xl`) | 600 | 28px (1.4) |

Existing components reused unchanged (`FieldLabel`, `Button`, `SecondaryButton`) keep their own inherited weights; no new weight is introduced by new markup.

### Typeface decision: Syne for page titles only

- **Decision:** adopt Syne SemiBold (600) as the display face for the page title (`<h2>` in the `AppLayout` page-heading `<header>`), through one CSS rule in the fork stylesheet: `header h2 { font-family: 'Syne', 'Inter', ui-sans-serif, system-ui, sans-serif; letter-spacing: -0.01em; }`. The existing `font-semibold text-xl` classes on those `<h2>` already give 600 and 20px. No page file and no Tailwind config is edited. Inter stays for body, tables, forms, the calendar, the timer and numbers.
- **Self-hosting:** `public/fonts/Syne-SemiBold.woff2` (converted from the skill's `Syne-SemiBold.ttf`, OFL 1.1; ship the license text next to it), `@font-face` with `font-weight: 600; font-display: swap;` in the fork stylesheet. One file only; no 400/500/700 files. The 600 file is optionally preloaded from the early-theme blade partial.
- **Rationale for not using Syne everywhere:** Syne is a wide geometric display face with a quirky lowercase; at the calendar's 10px/12px sizes and in dense tables it widens strings (more truncation of project and client names), reduces x-height legibility and has no tuned tabular figures for durations such as `01:23:45`, which Inter provides (`tnum`). The brand's own rule says Syne never goes above 700 and mid-weights feel soft; the web scale needs a text face. Display use keeps the identity visible on every page with no legibility risk.
- **Fallback:** if Syne fails or is blocked, the title falls back to Inter with no layout break (title width difference is absorbed by the existing header container). Spanish and English glyphs are covered (Latin and Latin-ext).
- **Not applied to:** `FormSection` titles (`h3`), dialogs, the auth card, the sidebar, the calendar, tables.

## Color

Dominant, secondary and accent follow the 60/30/10 split of the app: dominant is the content surface, secondary is cards, the sidebar and elevated layers, accent is the 10% highlight.

| Role | Dark | Light | Usage |
|------|------|-------|-------|
| Dominant (60%) | `#1C1C1C` (brand dark) | `#F9FCFD` (brand light) | Page and content surface (`--color-bg-primary`, `--theme-color-default-background`) |
| Secondary (30%) | `#262626` cards and inputs; `#141414` sidebar and chrome; `#2C2C2C` popovers | `#F9FCFD` cards (separated by a `#DDDDDD` border); `#EEF4F5` sidebar and chrome | Cards, sidebar, dropdowns, inputs |
| Accent (10%) | preset step 300 (Untangle `#00F5D4`) | preset step 400 for text, 500 for fills (Untangle `#007C6B`, `#066A5E`) | Reserved list below |
| Destructive | existing `--destructive` (`0 72% 60%` dark, `0 84.2% 60.2%` light), unchanged | same | Destructive buttons and error text only |

Accent reserved for (and nothing else):
1. Primary buttons (`PrimaryButton`, `--theme-color-button-primary-*`).
2. The timer start and break-inactive button (solid accent fill).
3. The active state of filter and select triggers (tinted fill and tinted border) and their leading icon.
4. Inline text links and hint actions (`text-accent-400` / `text-accent-500`: "Fix in calendar", "Open in Outlook", the sync spinner).
5. Checked state of Switch and Checkbox, and the open-state ring of a selected Outlook meeting block.
6. The single-series chart colour (`--theme-color-chart`) and goal and estimate progress fills.
7. The organization letter tile (solid accent fill) and the selected-swatch check.

Accent is never used for: body text, headings, card and input borders, sidebar navigation, time entry blocks (those use the project colour), Outlook meeting blocks (neutral), error or success states, or any full-width background.

### Accent scale step contract

The preset scales below are written to `--color-accent-50..950` as `R, G, B` triplets (existing format, decimal of the hex), once for `:root.light` and once for `:root.dark`. Each mode has its own scale; the same step number plays the same role in both modes, so the existing Tailwind classes (`text-accent-500 dark:text-accent-400`, `bg-accent-300/10`, ...) keep working.

| Step | Light mode role (surfaces `#F9FCFD`, `#EEF4F5`, `#EDF3F4`) | Dark mode role (surfaces `#141414` to `#303030`) |
|------|-----------------------------------------------------------|--------------------------------------------------|
| 50 | Tint fill under dark text (active select trigger) | Lightest; rarely used |
| 100 | Hover tint, `--color-accent-default` | Text on the accent-tinted fill (`--color-accent-foreground`) |
| 200 | Pale fill | Light text, selected-check icon, progress fill |
| 300 | Graphic object and border, at least 3:1 | Brand accent: primary text, primary-button tint source, select-active, chart, solid fill |
| 400 | Accent text (AA, 4.5:1) and icon, also at 80% opacity as an icon (3:1) | Hover and secondary accent text (AA) |
| 500 | Solid fill, button background, ring, accent text (AA, 5.7:1 or more) | Switch and ring fill (3:1 or more against `#262626`) |
| 600 | Button hover fill | Deep fill |
| 700 to 950 | Progressively darker | Progressively darker (tints for backgrounds) |

## Accent Picker (BRAND-02)

**Where:** the existing profile page section "Theme" (`Pages/Profile/Partials/ThemeForm.vue`). A new `Field` goes directly below the Theme select and above "Group similar time entries". It is one fork-owned component, `resources/js/branding/AccentPicker.vue`, added to `ThemeForm.vue` with one import and one element (ledger entry).

**Layout (top to bottom, `col-span-6 sm:col-span-4`):**
1. `FieldLabel` "Accent color" (group label for the radio group, `id` referenced by `aria-labelledby`).
2. A row of six circular swatches, 32px, `gap-3`, wrapping on narrow screens. Order: Untangle, Azure, Indigo, Violet, Ember, Graphite.
3. `FieldDescription` showing the selected preset: "{Name}. Used for buttons, links and selected items." The default carries "(default)": "Untangle (default). Used for ...".
4. When the selection is not Untangle, a ghost `Button` (`size="sm"`, `RotateCcw` icon): "Reset to Untangle". Hidden when already Untangle.

**Swatch anatomy:**
- Fill: the preset swatch colour for the **currently active mode** (light = step 400, dark = step 300), so the swatch previews what the accent looks like now. Swatch against its card surface is at least 3:1 in both modes (graphic object).
- Selected: 2px ring in `text-primary` with a 2px offset (`ring-2 ring-text-primary ring-offset-2 ring-offset-card-background`) plus a centered `Check` icon (16px, `text-[var(--color-on-accent)]`). The check is the non-color cue (WCAG 1.4.1); on-accent text on every swatch is at least 4.95:1.
- Hover: `Tooltip` with the preset name; no scale animation.
- Focus-visible: `ring-2 ring-ring ring-offset-2 ring-offset-card-background`.
- Not selected: no ring, no check.

**Semantics and keyboard:** `role="radiogroup"` with `aria-labelledby` the label; each swatch is `role="radio"`, `aria-checked`, `aria-label="<Name>"`. One swatch is in the tab order (the selected one), arrow keys (Left/Up previous, Right/Down next, wrapping) move and select, Home/End jump, Space selects. A visually hidden `aria-live="polite"` region announces "Accent color set to {Name}." on change.

**Behaviour:**
- Applies immediately on selection (like the Theme select): sets `data-accent` on `<html>` and writes `localStorage.accent`. No Save button, no animation on the color swap (instant, avoids a flash of mixed colors); the swatch ring uses `motion-safe:transition` at most 120ms.
- Persists per user on the server in the background (D-05, mechanism per RESEARCH). If the save fails the choice stays applied on this device and a notification appears: title "Couldn't save your accent color", body "It is applied on this device only. Try again later." (error state, see Copywriting).
- Resolution order: server value for the signed-in user, then `localStorage.accent`, then `untangle`. An unknown stored id falls back to `untangle`. Theme keeps its existing keys and order (`theme` in localStorage: `system` | `light` | `dark`, default `system`).
- Before first paint (no flash): a fork-owned Blade partial `resources/views/branding/early-theme.blade.php`, included in `resources/views/app.blade.php` and `resources/views/auth/oauth/authorize.blade.php` (replacing the inline copy there), sets the `light`/`dark` class and `data-accent` from `localStorage` synchronously. System mode uses `matchMedia('(prefers-color-scheme: light)').matches ? 'light' : 'dark'` so "no preference" resolves to dark (D-02; the old inline `matches ? 'dark' : 'light'` would resolve it to light). It also listens to `storage` events for `theme` and `accent` so other tabs follow, and to the system scheme change while the setting is `system`. Acceptable limit: on a brand-new device with a non-default server preference, one repaint after Inertia boots; every later load is flash-free.
- `theme.ts` keeps its API (`themeSetting`, `theme`, `useTheme`); its stray `console.log(preferredColor.value)` is removed (project rule: no `console.log` in shipped code). An `accent` ref with the same pattern (`useStorage('accent', 'untangle')`) is added in a fork-owned `resources/js/branding/accent.ts`, not in `theme.ts`.
- `<meta name="theme-color">` in `app.blade.php` becomes two tags with `media="(prefers-color-scheme: dark)"` `#1C1C1C` and `(prefers-color-scheme: light)` `#F9FCFD` (currently a static `#000000`).
- Command palette (priority 2, optional within the phase): an "Accent color" group with one command per preset ("Accent color: Azure"), next to the existing Theme group in `useCommandPalette.ts`.

**Theme select (existing):** unchanged except its helper line. Current: `System default: {{ preferredColor }}` shows the raw value `no-preference`. New copy: "Follows your device setting. Currently: {light|dark}." using the effective theme.

## Organization Icon (BRAND-03, D-06)

### Where it is managed

`Pages/Teams/Show.vue` renders `UpdateTeamNameForm.vue` first (Owner row, Organization Name, Currency). The icon field is added **inside that form** so the single existing Save button persists name, currency and icon together. It is placed between the "Organization Owner" row and the "Organization Name" field, in a `col-span-6 sm:col-span-4` block that mirrors the profile photo block in `UpdateProfileInformationForm.vue`. The block is one fork-owned component, `resources/js/branding/OrganizationIconField.vue`, added to `UpdateTeamNameForm.vue` with one import and one element (ledger). Section title and description of the form stay as they are.

### States of the field

| State | What the user sees |
|-------|--------------------|
| No icon, can edit | 80px tile with the organization letter (fallback), helper "No icon set. The first letter of the organization name is shown instead." Button "Upload icon" |
| Icon set, can edit | 80px tile with the image. Buttons "Replace icon" and "Remove icon" |
| New file selected (pending) | Tile shows the new image preview, hint "New icon selected. Save to apply it." Buttons: "Replace icon" and a "Remove icon" that only discards the pending selection (and, if there was a saved icon underneath, the saved one stays) |
| Saving | The existing Save button is disabled with its existing loading look; the icon buttons are disabled |
| Removing | "Remove icon" is disabled while its request runs |
| Validation error (client or server) | `FieldError` under the buttons with the specific message; the previous icon stays shown; pending selection is cleared |
| Read-only (no `canUpdateTeam`) | The tile only (no buttons, no input), with the line "Only organization owners and admins can change the icon." |

### Anatomy and rules

- Tile: 80px square, `rounded-md`, `object-cover` (non-square images are centre-cropped; no editor in this phase), `ring-1 ring-inset ring-border-secondary`, fixed `#F9FCFD` backing (`bg-[#F9FCFD]`) so a transparent logo drawn for a light background stays legible in dark mode. Fallback tile: solid `--theme-color-accent-solid` fill with the initial in `--color-on-accent`, Inter 600 (20px in the 80px tile, 12px in the 20px tile).
- Input: hidden `<input type="file" accept="image/png,image/jpeg">`, opened by the button (same as `selectNewPhoto`). SVG and GIF are not accepted (matches `Base64ImageRule`: PNG and JPEG, 1 MB decoded). Recommendation shown in helper: at least 128 x 128 px, square.
- Client validation before preview: type not PNG/JPEG shows the type error; size over 1 MB (1,048,576 bytes) shows the size error. No dimension limit is enforced.
- The file is read to a base64 data URL (`FileReader`), sent as `icon` in the existing organization update call (field name and API shape per RESEARCH; this contract only requires that sending `null` removes the icon).
- Remove: immediate request when a saved icon exists, no confirmation dialog (reversible by uploading again; same as "Remove Photo" for the user photo), followed by the success notification "Organization icon removed." and the fallback tile.
- After a successful save or removal: `router.reload({ only: ['auth', 'team'] })` (already done by the form) and an invalidation of the organization query, so the switcher updates without a full page reload.
- Accessibility: the file button has a visible text label (no icon-only); the tile has `alt="{Organization name} icon"` in the settings preview; the preview and status changes are announced through the existing notification region.

### Where the icon shows (everywhere the letter tile shows today, plus the switcher list)

One fork-owned presentational component, `resources/js/branding/OrganizationIcon.vue` (props: `name`, `iconUrl` nullable, `size` `sm` 20px | `lg` 80px), is the only renderer, so every place has the same fallback chain.

| Place | Size | Notes |
|-------|------|-------|
| `OrganizationSwitcher.vue` trigger (desktop sidebar and mobile header render the same component) | `sm` 20px, `rounded` | Replaces the `bg-blue-900` letter tile. Image `alt=""` (the organization name is the adjacent text) |
| `OrganizationSwitcher.vue` "Switch Organizations" list rows | `sm` 20px | New: placed between the status icon (check or arrow) and the name so organizations are recognisable; the name stays `truncate` |
| Settings preview (`OrganizationIconField`) | `lg` 80px | `alt` = "{name} icon" |

Fallback chain, identical everywhere: (1) uploaded `iconUrl` image; (2) if the image fails to load (`@error`) or `iconUrl` is null or empty, the letter tile: first grapheme of the trimmed name, uppercased (`Array.from(name.trim())[0]`, so emoji and surrogate pairs do not split), on the solid accent fill. The Untangle product mark and the app name area are not changed to the organization icon (decision: the "app logo" stays the product mark; the organization is already shown by the switcher directly under it).

Out of scope for this phase (deferred): organization icon in exported PDFs and invoices, in emails, and in the Filament admin panel.
