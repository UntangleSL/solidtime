# Phase 3.2 Plan 06: Accent state, server sync, picker and palette commands Summary

A user can now pick one of six accents from the profile Theme section or the command palette. The choice applies at once as a single `accent-<id>` class on `<html>`, so charts and calendar colours recompute. Theme and accent are saved together to `PUT /user/appearance` 400 ms after the last change, once per page load, with a one-time migration of the legacy localStorage theme.

## What was built

- **`accent.ts`**: `accentSetting` is `useStorage('accent', 'untangle')`, the raw key the pre-paint script reads. `activeAccent` passes stored values through the `isAccentId` allow-list (T-03.2-20). `applyAccentClass` removes only `accent-<preset>` classes. `setAccent` writes the setting and swaps the class immediately. `useAccent` applies the class and owns one watcher, which also covers other tabs.
- **`useAppearance.ts`**: module-level state, idempotent across AppLayout mounts.
  - One `watchDebounced([themeSetting, activeAccent], save, { debounce: 400 })` runs in a detached effect scope.
  - `reconcile()` runs only when the server snapshot (update_url, theme, accent) changes. With no unsaved local change, it adopts non-null server values without a PUT. It seeds once when a server value is null and the device value is not the default.
  - `save()` skips unchanged and in-flight pairs. On failure the choice stays applied on the device, and the user gets `accent_save_failed_title` / `accent_save_failed_body` only when the accent changed. Theme-only failures stay silent.
  - Guests (`update_url` null) never send anything.
- **`AppLayout.vue`** (core, +2 lines): import and `useAppearance()` right after `useTheme()`.
- **`AccentPicker.vue`**: `Field` / `FieldLabel` with an id referenced by `aria-labelledby`, and `role="radiogroup"` holding six 32 px `role="radio"` swatches.
  - Each swatch is filled with the preset colour for the effective mode. The selected one has a `ring-text-primary` ring with offset and a `Check` icon in `--color-on-accent`. Focus-visible uses `ring-ring`, and the ring transition is `motion-safe` at 100 ms.
  - Roving tabindex. Arrow keys wrap and select as they move; Home, End, Space and Enter also select, and focus follows the selection.
  - A tooltip shows the name. The description uses `formatLabel` with the "(default)" marker for Untangle. A ghost `Reset to Untangle` button appears only for other presets. A polite live region announces "Accent color set to {Name}.".
- **`ThemeForm.vue`** (core): imports `AccentPicker` and places it after the Theme field. The helper is now a computed `formatLabel(theme_helper, { mode })` built from the effective theme, so it reads "Follows your device setting. Currently: light." The unused `usePreferredColorScheme` was dropped.
- **`theme.ts`** (core): stray `console.log` removed, nothing else.
- **`e2e/profile.spec.ts`** (core test): the helper assertion now expects 'Follows your device setting.'.
- **`accentCommands.ts`**: commands "Accent color: <Name>" with the `Palette` icon and keywords accent/color/colour/theme/name, in group `accent`. Priority is `150 + (6 - index)`.
- **`commandPaletteCommands.ts`** (core): `'accent'` was added to `CommandGroup` and `accent: 150` to `GROUP_PRIORITIES`.
- **`useCommandPalette.ts`** (core): new group `{ id: 'accent', heading: 'Accent color' }` after Theme, plus an `accentCommands` computed spread after `themeCommands`.
- **`presetParity.test.ts`**: checks that the PHP enum cases, `ACCENT_IDS`, `untangle` + the light CSS blocks (and the dark blocks), and the `presets` keys in both lang/en and lang/es are the same ids in the same order.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Test isolation across `vi.resetModules()`**
- **Found during:** Task 1
- **Issue:** VueUse `useStorage` syncs every instance in the same window through a custom storage event. The previous test's module copy, with its persistence watcher, kept reacting and sent extra PUTs.
- **Fix:** the watcher runs in a detached `effectScope`. The new export `disposeAppearanceSync()` stops it and resets module state, and the test calls it in `afterEach`. Runtime behaviour is unchanged: the app never calls it.
- **Commit:** 6fdab01d

**2. [Rule 2 - Correctness] In-flight guard in `save()`**
- **Issue:** if a seed PUT is still running when the debounced watcher fires after an adopt, the same pair would be sent twice.
- **Fix:** `inFlight` holds the pair being sent, and an identical pair is skipped (T-03.2-21).
- **Commit:** 6fdab01d

**3. [Rule 3 - Blocking] Worktree base and tooling**
- The worktree was cut from upstream b46f0157. It was reset (clean tree) to 8fbb5c5e as the exec rules require.
- `vue-tsc` failed on `../../vendor/tightenco/ziggy` because the worktree had no `vendor`. A gitignored `vendor` junction to the main checkout was created, the same as in sibling worktrees. Nothing was committed for this.

**4. Parity test reads PHP and lang files with `node:fs`, not `?raw` imports.** This is consistent with `sourceFiles.ts` (03.2-01), and the CSS is read through `readShippedCss`. The test also checks the dark CSS blocks and `lang/es`.
