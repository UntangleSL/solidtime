# Phase 3.2: Appearance & Untangle Branding - Context

**Gathered:** 2026-11-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Make solidtime look like an Untangle tool by default and let each user tune it: Untangle brand colours as the default theme, light/dark/system theme and an accent (highlight) colour per user, and an organization icon that admins can upload in workspace settings. Readability (contrast) must hold in every combination.

Requirements: BRAND-01..BRAND-04.

Not in this phase: calendar layout and interaction changes (Phase 3.1, which may run in parallel), any change to authentication or data.

</domain>

<decisions>
## Implementation Decisions

### Existing behaviour (found in code)
- **D-01:** Theme already exists: `resources/js/utils/theme.ts` stores `theme` (system / light / dark) in localStorage and toggles `.light` / `.dark` on `<html>`; the profile `ThemeForm.vue` and the command palette set it; `views/auth/oauth/authorize.blade.php` inlines the same logic. Colour tokens live in `resources/js/packages/ui/styles.css` (`:root.dark`, `:root.light`, shared `:root`) and are mapped in `resources/js/packages/ui/tailwind.theme.js`; the accent palette is hardcoded Tailwind sky (`--color-accent-50..950`).

### Default theme (owner, 2026-11-16)
- **D-02:** Default theme mode stays "follow the system" (light or dark by OS, dark when the OS gives no preference), both in Untangle colours. Users can still override in their profile.

### Untangle branding (BRAND-01)
- **D-03:** Untangle brand colours become the default palette in both light and dark: background/surface tones, text, borders and the default accent. Source of truth: the `untangle-brand` / `untangle-design` skills (colours, Syne typography, dark/light rules). Whether to adopt the brand typeface is Claude's discretion (only if it keeps tables and the calendar readable). Changes go through the existing CSS variables so the whole app (including the calendar and Phase 3 meeting blocks) follows.

### Accent colour (owner, 2026-11-16: palette)
- **D-04:** Each user picks an accent (highlight) colour from a **preset palette of 6-8 colours**, Untangle's accent being the default. Every preset is defined for light and dark and verified for contrast; no free colour picker. Implemented by swapping the `--color-accent-*` scale (and dependent tokens) at runtime.
- **D-05:** Persistence of theme and accent: per user. Storing on the server (user preference) so it follows the user across devices is preferred; localStorage fallback before the page loads to avoid a flash. Exact mechanism is Claude's discretion; it must not touch the public `/api/v1` OpenAPI spec unless done through an existing endpoint pattern.

### Organization icon (BRAND-03)
- **D-06:** Organization owners/admins (whoever can edit the organization today) can upload, replace and remove an organization icon in the organization / workspace settings page. Shown in the organization switcher and anywhere the organization letter tile appears today (`OrganizationSwitcher.vue`), falling back to the current letter tile. Follow the existing user profile-photo pattern (base64 upload, `Base64ImageRule`, public disk, accessor with fallback, removal) from `UserUpdateRequest` / `UserController` / `User::profilePhotoUrl`.

### Readability (BRAND-04)
- **D-07:** All theme x accent combinations meet WCAG AA contrast for body text and controls; calendar time entries and Outlook meeting blocks stay readable and distinguishable in light and dark.

### Typeface (owner, 2026-11-17)
- **D-10:** No Syne anywhere: it is a presentation typeface. Inter stays the only font, page titles included. Supersedes the UI-SPEC "Syne for page titles" decision and the D-03 typeface discretion.

### Carried forward
- **D-08:** Fork isolation and the core-file ledger (`docs/m365/TOUCHED-CORE-FILES.md`) apply: theme/branding touches core files (styles.css, tailwind theme, theme.ts, org settings, Organization model/migration), so keep edits additive and ledger every one; prefer new files for fork logic. New DB column/migration for the organization icon must be additive with a `down()`.
- **D-09:** Testing (owner, 2026-11-10): automated tests in GitHub CI for each behaviour (PHPUnit for the icon upload/permissions/removal; Vitest for theme/accent resolution and persistence; a contrast check of the presets). Plans that touch independent files share a wave so they can run in parallel; batch CI waits.

### Claude's Discretion
- The 6-8 preset colours (Untangle default first), the settings UI for accent (profile page next to ThemeForm), icon size limits and formats, whether the app logo/name area also shows the organization icon.

</decisions>
