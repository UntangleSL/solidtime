# Phase 3.2 Plan 01: Untangle tokens, six accent presets and the contrast gate Summary

The app now defaults to the Untangle palette in light and dark through one fork stylesheet that overrides the shared CSS variables at `html:root.<mode>` specificity. Six accent presets ship as `html:root.<mode>.accent-<id>` blocks, and a 493-case Vitest gate checks every theme x accent combination against the UI-SPEC contrast table, reading the shipped files. Inter is still the only typeface (owner override D-10: no Syne file, @font-face or heading rule).

## What was built

- **`resources/css/untangle-theme.css`** (fork-owned): the full UI-SPEC neutral ladder for both modes (hex for every surface, text and border token so chroma can parse `--color-bg-background`). It also holds the accent-dependent tokens that change (dark: button border 0.45, chart 300; light: button 500/600/600, text `#F9FCFD`), the new `--color-on-accent`, `--theme-color-accent-solid` and `--theme-color-accent-solid-hover`, and the Untangle baseline scale (dark 300 = `0, 245, 212`, light 400 = `0, 124, 107`). The eight `--m365-*` properties use the exact UI-SPEC formulas, and every `var()` inside the six colour formulas has a literal fallback. The file contains no pure white or black and no font rules.
- **`resources/css/accent-presets.css`** (fork-owned): generated from the UI-SPEC "Light/Dark mode scales" tables by a throwaway scratchpad script (not committed). It has 10 blocks (azure, indigo, violet, ember, graphite in each mode), each with 11 decimal triplets. There is no untangle block because Untangle is the baseline.
- **`resources/css/app.css`** (core): two `@import` lines placed directly after the styles.css import and before the Inter @font-face.
- **`resources/js/branding/accentPresets.ts`**: the six presets in UI-SPEC order, with names and swatches (light = step 400, dark = step 300), `ACCENT_IDS`, `DEFAULT_ACCENT = 'untangle'` and the `isAccentId` guard.
- **`resources/js/branding/contrast.ts`**: pure helpers.
  - `parseCssBlocks` and `resolveTokens` (the mode baseline plus the preset block).
  - `expandVars`, `parseColor` and `resolveColor`: hex, `rgb()`/`rgba()` over triplets, `var()` with fallbacks, `color-mix(in srgb, ...)` with premultiplied alpha, and `transparent`.
  - `composite`, `relativeLuminance` and `contrastRatio` (WCAG 2.x).
  - `normaliseFormula` and `findCustomPropertyDeclarations` for the drift guard.
- **`resources/js/branding/tokens.test.ts`** (16 tests): checks the brand anchors and both ladders, the new tokens and the `--m365-*` fallbacks, selector scoping, no pure white or black, import order, no Syne, the preset blocks, the preset list, `isAccentId`, and that the swatches equal the CSS.
- **`resources/js/branding/contrast.test.ts`** (493 cases, all passing). It covers:
  - helper unit tests;
  - structure: 11 steps per preset x mode, monotonic scales, the anchors, no pure white or black;
  - neutral rows per mode;
  - light accent rows (12 per preset) and dark accent rows (14 per preset);
  - solid accent and swatch-check rows;
  - time entries: text-primary and text-primary at 85% over `chroma.mix(project, bg-background, 0.65, 'lab')` for the 19 project colours, the 6 extremes and the break colour at 0.75, in both modes;
  - Outlook meeting rows (11 per preset x mode) resolved from the `--m365-*` formulas;
  - the 3.1/3.2 drift guard, which scans `resources/js/m365/calendar` (read only).
- Measured values match the UI-SPEC "Measured" column, for example: light text-quaternary 5.34 / 4.95 / 4.91; Untangle light meeting subject on fill 13.01; dark bar vs fill 4.79. The worst time-entry case is 4.59 (light, `#000000`, text at 85%).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Stylesheets are read via `node:fs` instead of Vite `?raw` imports**
- **Found during:** Task 1
- **Issue:** Vitest returns `""` for every `.css` module, query included, because `test.css` is off in the shared `vitest.config.ts`. A first attempt with `new URL(template, import.meta.url)` was rewritten by Vite's asset plugin and read the wrong file.
- **Fix:** added the test-only helper `resources/js/branding/sourceFiles.ts`: `readShippedCss` reads from `resources/css` via `fileURLToPath` and `path.resolve`, and `readSourceTree` serves the drift-guard scan. The gate still reads the real shipped files, never a copy. The key_link pattern `untangle-theme.css\?raw` does not appear literally. The drift guard reads `resources/js/m365/calendar` through the same helper rather than `import.meta.glob`, because a glob would also blank any `.css` there. `vitest.config.ts` (core) was not edited.
- **Files:** `resources/js/branding/sourceFiles.ts` (new, not in files_modified; it was named `shippedCss.ts` in commit 521f84ad and renamed in e58c5478)
- **Commits:** 521f84ad, e58c5478

**2. [Rule 3] Agent branch re-based at startup**
- The worktree branch was created from upstream `main` (b46f0157), not `feature/m365-integration`. Before any work, it was reset to `feature/m365-integration` (1e5f9c4a). No work was lost.

### Reported for the owner (not tuned)

**3. UI-SPEC inconsistency: the Untangle dark scale is not monotonic between steps 200 and 300**
- The UI-SPEC pins Untangle dark step 300 to the brand teal `#00F5D4` (relative luminance 0.70). Its own step 200 `#9CDFD2` is darker (0.645). This contradicts the UI-SPEC gate statement "step ordering is monotonic (dark darkens with step)". Every other preset x mode is strictly monotonic.
- Per plan Task 3 step 3, no value was changed. The monotonic test exempts only that named pair (`BRAND_ANCHOR_EXEMPTION`). A companion test pins the exemption to the anchor and checks that step 100 is still above step 300 and step 400 below step 200.
- All contrast rows that use steps 200 and 300 pass: dark step 200 on hover is 8.74 or more, and dark step 300 text is 8.13 or more for Untangle.
- **Owner choice:** (a) accept as is (recommended: the teal anchor is a brand rule and no readability row fails); or (b) lighten Untangle dark step 200 above the teal's luminance (for example near `#B8F3E9`) and remove the exemption.
