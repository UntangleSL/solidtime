# Phase 03.2 Plan 07: Organization icon front end Summary

Organization icon UI: one `OrganizationIcon` renderer (uploaded image on a fixed `#F9FCFD` backing, otherwise the first grapheme on the solid accent fill). It now replaces the `bg-blue-900` tile in the switcher trigger and also appears in every "Switch Organizations" row. Organization Settings gets an icon field whose upload is sent by the existing single Save button.

## What was built

- `organizationIcons.ts`: `firstGrapheme(name)` (trimmed, `Array.from` so emoji are not split, uppercased), `organizationIconPath(id)` = `/organizations/{id}/icon`, `useOrganizationIcons()` → `{ icons, iconFor(id) }` from `appearance.org_icons` (a missing map means no icons).
- `OrganizationIcon.vue`: props `name`, `iconUrl`, `size: 'sm' | 'lg'`, `alt` (default `''`). Image when the URL is non-empty and has not failed. `@error` switches to the letter tile, and a new URL resets the failure. sm is `h-5 w-5 rounded`; lg is `h-20 w-20 rounded-md ring-1 ring-inset ring-border-secondary`. The tile uses `text-xs` in sm and `text-xl` in lg, with `font-semibold font-sans` (Inter).
- `OrganizationSwitcher.vue` (core): the trigger tile becomes `<OrganizationIcon size="sm">`, and each switch row gets one between the check/arrow icon and the truncated name. `data-testid` and the texts are unchanged.
- `OrganizationIconField.vue`: the UI-SPEC states table.
  - It shows the empty, saved, pending and read-only states, plus the client type error (PNG/JPEG) and size error (≤ 1,048,576 bytes).
  - `commit()` POSTs `{icon: dataUrl}` to the global axios. A 422 shows `errors.icon[0]` (or `message`); any other failure shows the generic message. The pending icon is cleared either way. It resolves `true` on success or when there is nothing to send, `false` on failure.
  - Remove DELETEs a saved icon, then shows the `icon_removed` notification and runs `router.reload({ only: ['appearance'] })`. With only a pending icon, Remove just discards it.
  - The buttons are disabled while the form saves (`disabled` prop) or while a removal runs.
- `UpdateTeamNameForm.vue` (core):
  - Adds the import, the `iconField` ref and the `<OrganizationIconField>` between the owner row and the name.
  - Calls `await iconField.value?.commit()` after `api.updateOrganization` resolves.
  - The reload now asks for `['auth', 'team', 'appearance']` (this refreshes the switcher).

## Deviations from Plan

1. **[Executor rules] Push and the wave-2 CI gate (Task 2 steps 4-5: push, Gate W, Gate B) were not run.** The executor rules for this run say "Do NOT push"; the orchestrator owns merging, pushing and the batched CI. The `gh auth status` / sibling-push precondition was therefore not evaluated. Gate W (eight workflows) and Gate B (≥ 12 Appearance PHPUnit PASS lines) are still open for the orchestrator on the merged wave-2 HEAD.
2. **[Rule 2 - Accessibility] The letter tile is `aria-hidden` when `alt` is empty.** Without it, a switcher row's accessible name would read "A Acme". The empty-alt image is already decorative, so the tile now matches it. Existing e2e `getByRole('menuitem', { name })` lookups keep matching. Commit 38f4e359.
3. **[Rule 1 - Test reliability] The switcher test imports `OrganizationSwitcher.vue` statically.** A dynamic import inside the test went over the 5 s Vitest timeout on a cold transform of the UI barrel.
4. **Worktree setup.** The worktree started from an old upstream commit, so it was reset to 8fbb5c5e as the worktree notes say. It also got `node_modules` and `vendor` junctions to the main checkout. Both are gitignored and nothing from them was committed.

## Notes for the orchestrator / verifier

- The plan specified a client-side contract for 03.2-05 and this code follows it exactly. POST `/organizations/{id}/icon` with `{icon}` should return 200 `{url}`, or 422 `{message, errors.icon[]}`. DELETE should return 204. `appearance.org_icons` should map organization id to URL. The global axios sends the XSRF header for these web routes.
- If the organization update succeeds but the icon upload fails, the existing "Organization updated successfully" notification still shows. The icon error is shown under the field. This is the behaviour the plan describes.
- Browser proof is planned for 03.2-08: the upload, the switcher image, the fallback and the read-only state.
