# Phase 03.2 Plan 03: Contrast class fixes Summary

The stopped timer now draws on the solid accent token with an on-accent icon, and the four pale-accent usages (export link, selected client check, goal and estimate fills) use a darker step in light mode and keep the pale step in dark mode.

## What was built

- `TimeTrackerStartStop.vue`: `text-white` removed from the `primary` and `break` base strings. Each compound variant now carries its own text colour:
  - primary/active (running): `bg-red-400/80 ... text-white` (unchanged look)
  - primary/inactive and break/inactive: `bg-[color:var(--theme-color-accent-solid)] hover:bg-[color:var(--theme-color-accent-solid-hover)] focus:bg-[color:var(--theme-color-accent-solid-hover)] text-[color:var(--color-on-accent)]`
  - break/active (amber): `text-[#1C1C1C]`
- e2e: `assertTimerIsStopped` (command-palette.spec.ts:44) and `assertThatTimerIsStopped` (utils/currentTimeEntry.ts:59) now match `/bg-\[color:var\(--theme-color-accent-solid\)\]/`.
- ExportData link: `text-accent-500 hover:text-accent-600 dark:text-accent-200 dark:hover:text-accent-300` (font-semibold kept).
- ClientDropdownItem selected icon: `text-accent-500 dark:text-accent-200`.
- GoalProgressBar in-progress fill and EstimatedTimeProgress under-estimate fill: `bg-accent-400 dark:bg-accent-200`.
- `resources/js/branding/contrastFixes.test.ts` (113 lines, 11 tests): mounts the timer in its four states, plus a check that each state has exactly one text colour. Mounts ClientDropdownItem (selected and unselected) and EstimatedTimeProgress (under and over the estimate). Reads ExportData.vue, GoalProgressBar.vue and EstimatedTimeProgress.vue with `?raw` to guard the source.
