# Phase 03.2 Plan 02: Appearance module Summary

Fork module `app/Appearance/` that stores each user's theme and accent preset in a side table through a session-only `PUT /user/appearance`, re-validates them on read, and shares them (plus preset ids, update URL and the phase copy) with every Inertia page as the `appearance` prop. Core is touched in one line (`config/app.php`).

## What was built

- **AccentPreset** enum: untangle, azure, indigo, violet, ember, graphite; `values()` returns them in that order.
- **user_appearance_settings** table (additive, has `down()`): uuid id, unique `user_id` FK to users with cascade on delete/update, `theme` string(16) nullable, `accent` string(32) nullable, timestamps. **UserAppearanceSetting** model (HasUuids, `@property` annotations, not audited).
- **PUT /user/appearance** (`appearance.update`): middleware `web, auth:web, auth.session, verified, throttle:60,1,appearance:`, no route parameter, not under `api/` (openapi.json untouched). It only changes the keys that were sent, null resets a value, `user_id` in the body is ignored, and it answers `200 {theme, accent}`.
- **AppearanceUpdateRequest**: `theme` in system|light|dark, `accent` via `Rule::enum(AccentPreset::class)`, both `sometimes|nullable|string`; an empty body is a 422.
- **AppearanceResolver** (plain bind): `settingsFor(?User)` memoised on `request()->attributes` (`appearance.settings.<id>`) and re-validated on read (unknown values come back as null); `bootPayload()` for the pre-paint partial (03.2-04); `sharedProps()` for the prop.
- **ShareAppearanceInertiaData**, pushed onto the web group: `Inertia::share('appearance', fn () => resolver->sharedProps())`.
- **lang/en|es/branding.php**: 23 `ui` keys, 6 `presets`, `validation.icon_dimensions`, values from the UI-SPEC Copywriting Contract with Laravel `:name`/`:mode` placeholders. The `accent_save_failed` notification is split into a title ("Couldn't save your accent color.") and a body ("It is applied on this device only. Try again later.").
- **appearanceProps.ts**: `ThemeSettingValue`, `BrandingLabels` (23 explicit keys), `AppearanceProps` (optional `org_icons`), `useAppearanceProps()` (computed with safe defaults; a partial labels map is filled with empty strings), `formatLabel()` (unknown placeholders stay as written).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Empty-body validation without `required_without`**
- **Found during:** Task 1
- **Issue:** With `sometimes`, `required_without` never runs on an empty body, so `{}` would pass. Without `sometimes`, `required_without` would reject `{accent: null}`, which is how a value is reset.
- **Fix:** Kept `sometimes|nullable` plus the allow-lists, and added a FormRequest `after()` hook that adds an error when neither `theme` nor `accent` is present.
- **Files modified:** app/Appearance/Http/Requests/AppearanceUpdateRequest.php
- **Commit:** 05d604a1
