# Phase 03.2 Plan 04: Pre-paint early-theme partial Summary

One fork Blade partial puts the signed-in user's theme and accent on `<html>` before the first paint (server value, then localStorage, then system/untangle; system resolves to dark unless the OS asks for light), shared by the Inertia root view and the OAuth authorize page, and proven by a Vitest suite that executes the shipped script.

## What was built

- **`resources/views/branding/early-theme.blade.php`** (fork-owned): `@inject` of `AppearanceResolver`; `<script>window.__APPEARANCE__ = {{ Js::from(bootPayload()) }};</script>`; then `<script data-early-theme>` with a self-invoking ES5 function and no Blade syntax:
  - safe storage helpers (reading `window.localStorage` itself, `getItem` and `setItem` all in try/catch);
  - pick = valid server value, else valid stored value, else `system` / `untangle`;
  - resolve = non-system theme is itself; system is `light` only when `matchMedia('(prefers-color-scheme: light)').matches`, otherwise `dark` (D-02, same as theme.ts; a missing `matchMedia` also gives dark);
  - apply = remove `light`/`dark`, add the mode; remove every other `accent-<id>` from the payload list, add `accent-<picked>`; nothing else on `<html>` changes;
  - valid server values are written to localStorage as raw strings, so `useStorage` starts from them;
  - listeners: `storage` (keys theme, accent, or null) re-picks from localStorage and re-applies; `change` on the light media query re-applies while the setting is system (`addListener` fallback for old Safari);
  - the whole body is in try/catch.
- **`app.blade.php`** (core, 3 lines): `@include('branding.early-theme')` right after the viewport meta (before favicons, `@routes`, `@vite`); `theme-color` `#000000` replaced by two media-scoped metas `#1C1C1C` / `#F9FCFD`. `msapplication-TileColor` and the mask-icon colour are unchanged.
- **`auth/oauth/authorize.blade.php`** (core): the 45-line inline theme IIFE is deleted and replaced by `@include('branding.early-theme')` before `@vite('resources/css/app.css')`; `<html lang="en" class="light">` stays as the no-script default. The page now also gets the accent and the D-02 dark default (the old copy resolved "no preference" to light).

## Tests

- **`tests/Feature/Appearance/AppearanceBootPartialTest.php`** (6 tests, CI only, needs Postgres): guest `/login` payload with nulls; saved dark/violet on `/dashboard`; unknown stored values (blue/rose) printed as nulls; partial before `const Ziggy=`, before the first `/build/assets/` tag, the first stylesheet link and `</head>`, payload before logic; theme-color metas; authorize view rendered for a signed-in user (factory-made Passport client, empty scopes, current request, dummy token) carries the partial with the user's payload, no inline copy, and sits before the stylesheet. Expected payload strings are built with `Js::from(...)->toHtml()`.
- **`resources/js/branding/bootScript.test.ts`** (26 tests): reads the Blade file from disk, extracts the `<script data-early-theme>` body, asserts no Blade expression, and runs it with `new Function` under a controllable `matchMedia` stub and happy-dom localStorage. Covers precedence, defaults for the three preferences, invalid stored and server values (never stored), throwing `getItem`/`setItem`, throwing `window.localStorage` getter, missing `matchMedia`, class hygiene (`light accent-azure keep-me`), storage events for theme, accent and unrelated keys, system scheme flips with setting system and dark, and the 9-case drift guard against `@/utils/theme` (re-imported after `vi.resetModules()`).
- Mutation check: changing the system fallback from dark to light in the Blade file made 7 tests fail (including two drift-guard cases); reverted.
