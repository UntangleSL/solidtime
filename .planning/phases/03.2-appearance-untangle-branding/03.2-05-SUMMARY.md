# Phase 03.2 Plan 05: Organization icon backend Summary

Organization icon upload, replace and removal for owners and admins (organizations:update), stored as uuid-named PNG/JPEG files on the public disk and recorded in a fork side table. The switcher gets the icons of the user's own organizations through `appearance.org_icons`, and deleting an organization removes its file.

## What was built

- **Table and model.** `organization_icons` (additive migration with `down()`), one row per organization, FK `cascadeOnDelete()->cascadeOnUpdate()`. `OrganizationIcon` uses core `HasUuids` and is not audited.
- **Request.** `OrganizationIconRequest`: `icon` required, string, `new Base64ImageRule` (core rule, unchanged: PNG/JPEG by content sniffing, 1 MiB decoded). An `after()` validator decodes the value and runs `getimagesizefromstring`; unreadable or any side outside 32-1024 px adds `branding.validation.icon_dimensions` to `icon`.
- **Controller** (`extends App\Http\Controllers\Web\Controller`): `store()` and `destroy()` both throw `AuthorizationException` unless `hasPermission($organization, 'organizations:update')` (membership is checked inside PermissionStore). `store()` writes `organization-icons/<uuid>.<ext>` (extension from the sniffed MIME type) with public visibility, `updateOrCreate`s the row, deletes the previous file only after the row points at the new one, and answers `{url}`. `destroy()` deletes row and file and answers 204 also when there is no icon.
- **Routes** (inside the existing `web, auth:web, auth.session, verified` group, not under `api/`): POST and DELETE `/organizations/{organization}/icon`, both `whereUuid('organization')` and `throttle:20,1,org-icon:`, named `organizations.icon.store` and `organizations.icon.destroy`. The client builds the path from the organization id.
- **Listener.** `DeleteOrganizationIconFile` handles `BeforeOrganizationDeletion` and registers the file deletion with `DB::afterCommit`, so a rolled-back deletion keeps its icon. Registered in `AppearanceServiceProvider::boot()` (core event discovery is off, so it is registered exactly once).
- **Prop.** `AppearanceResolver::sharedProps()` now carries `org_icons` (public method `organizationIcons(?User)`): `array<string, string>` keyed by organization id, only for organizations where the session user is a member, `[]` for guests. Still evaluated lazily inside the share middleware closure, which is unchanged.
- **Tests.** `OrganizationIconTest` (15 tests): upload (owner, admin, JPEG extension), replace, remove (owner, admin, idempotent), route shape (middleware, throttle, uuid constraint, not under api/), permission matrix (manager, employee, other organization's owner -> 403 for both verbs, nothing changed), guest JSON 401, unknown uuid and non-uuid 404, validation matrix (missing, non-string, invalid base64, CSV, SVG with script, GD GIF, PNG over 1 MiB, 16x16, 1100x40, 40x1100 -> 422; 32x32, 1024x1024, test.png -> 200), prop scoping (member of A with icon and B without, C not a member with icon -> only A), guest prop `[]`, organization deletion removes the file and row and leaves another organization's icon, listener registration.

## Deviations from Plan

1. **[Executor rules] No push.** The plan's Task 2 pushes to `origin/feature/m365-integration`; the orchestrator rules for this wave forbid pushing (the orchestrator merges the worktree branch), so the acceptance check on `origin` is left to the orchestrator.
2. **[Rule 3 - Blocking] Pint renamed a helper.** Pint's `php_unit_method_casing` turned a private helper `testPng()` into `test_png()`; it was renamed to `samplePng()` before the commit.
3. **[Rule 2 - Coverage] Extra tests.** Added JPEG upload, admin removal, a 40 x 1100 case, the 1024 x 1024 upper bound, missing and non-string bodies, a listener-registration test, and a throttle assertion on the route test. The organization deletion test runs the real event (not faked) so it proves the provider wiring end to end; if a CI extension adds its own `BeforeOrganizationDeletion` listener that needs more fixtures, that test is the one to look at.
4. **Prop query.** The plan says "the user's organization ids"; the implementation uses a `members` subquery (`select organization_id from members where user_id = ?`) instead of the `organizations()` BelongsToMany, so it stays one query without loading pivot columns.
5. **Worktree setup.** The worktree was cut from an old upstream commit and had no `vendor`; it was reset to 8fbb5c5e (clean tree) per the executor rules and a `vendor` junction to the main checkout was created (gitignored).
