# Phase 03.2 Plan 08: Appearance e2e spec and Phase 3.2 core-file ledger Summary

Seven Playwright tests now cover the phase in a real browser, and the core-file ledger ends with a `## Phase 3.2` section built from the 03.2 commit log. The tests check the Untangle default (Inter only), server pre-paint with every JS bundle blocked, an accent switch that recolours the chart and persists, the 320 px picker, and the organization icon flows.

## What was built

`e2e/appearance.spec.ts` (fork-owned, 366 lines, 7 tests):

1. **Untangle is the default palette for a new user.** In light mode: `light` and `accent-untangle`, `--color-accent-400` = `0, 124, 107`, `--color-bg-primary` = `#F9FCFD`. Body font is Inter, and no body, h1-h3 or loaded FontFace mentions Syne (D-10). In dark mode: `dark`, and `--color-accent-300` = `0, 245, 212`.
2. **Saved theme and accent are applied before any script runs.** The test picks Dark and Violet on the profile page and waits for a `PUT /user/appearance` 200 whose body has `{theme: dark, accent: violet}`. It then opens a new page in the same context with the OS set to light, aborts `**/build/assets/*.js`, and clears localStorage with `addInitScript`. Result: `dark` and `accent-violet`, no `light`, and `--color-accent-300` = `222, 169, 254`. It also checks that at least one bundle was actually aborted.
3. **An accent switch recolours the dashboard chart and persists.** It creates a 1 h entry through the API and takes a settled screenshot of the "This Week" chart canvas. It then runs the palette command `Accent color: Ember` and waits for the PUT. Checks: `accent-ember` is set, `--m365-meeting-bg` contains `156, 69, 4`, and a second settled screenshot differs from the first. After a reload, `accent-ember` and `--color-accent-500` are still Ember.
4. **The accent picker selects, resets and fits a 320 px screen.** Azure gets `aria-checked=true` and the reset button appears. Reset brings back Untangle and hides the button. At 320 x 800, all six radios are visible and their right edge is ≤ 320.
5. **Owner uploads an organization icon and sees it in the switcher.** `**/storage/organization-icons/**` is fulfilled with test.png. The test sets `#organization_icon`, clicks Save and waits for the icon POST to return 200. The switcher image has a `/organization-icons/` src and `naturalWidth > 0`, and is still there after a reload. Remove icon shows the toast "Organization icon removed." and the switcher goes back to the letter tile.
6. **A broken icon URL falls back to the letter tile.** The test renames the org to "Zephyr Icons" with the same Save and uploads an icon. It then routes the icon URL to a 404 and reloads: the switcher has no image and the letter tile shows `Z`.
7. **An employee sees the organization icon read-only.** The read-only note is visible. There is no Upload or Remove button and no `#organization_icon` input.
