## Summary

The existing theme system is small and clean. Every colour in the UI is a CSS variable on `<html>` (`.light` / `.dark` class) and the accent is an `r, g, b` triplet scale `--color-accent-50..950` consumed by Tailwind as `rgba(var(--color-accent-N), <alpha-value>)`. That means **the whole of BRAND-01/02/04 can be done by one new fork-owned stylesheet loaded after the shared one, with zero edits to `styles.css`, `tailwind.theme.js` or `tailwind.config.js`**: it overrides the neutral tokens with Untangle hex values per mode and defines the accent scales per preset per mode under `html:root.<mode>.accent-<id>` selectors. The accent is switched with a **class on `<html>`** (not an inline style or data attribute) because `useCssVariable` (used by every chart and by the calendar entry colour mixing) only watches `class` mutations (`useCssVariable.ts:29` `attributeFilter: ['class'],`).

For persistence, the cleanest fork-isolated design is a **fork-owned side table + web routes + a Blade boot partial**, mirroring the Phase 2/3 pattern (`app/Microsoft365/`, web-group middleware that calls `Inertia::share`, routes outside `api/`, additive migration loaded from the provider). It never touches `User`, `Organization`, `ShareInertiaData`, `UserResource`, `OrganizationResource` or `openapi.json`. Server values are injected into `<head>` by a small Blade partial so the correct `.dark`/`.light` and `accent-*` classes exist before first paint on any device (today there is **no** pre-paint script on Inertia pages at all: `app.blade.php` has a bare `<html lang=...>` and the class is only added when `AppLayout` mounts). localStorage (`theme`, new `accent`) stays as the guest/offline fallback and as the migration source for existing users.

The organization icon follows the profile-photo pattern exactly (base64 in, `Base64ImageRule` reuse, public disk, uuid filename, delete previous), stored in a fork side table and delivered to the UI as an `appearance.org_icons` map (organization id to URL) so `ShareInertiaData` is untouched. Only owner and admin hold `organizations:update` today, which is exactly "whoever can edit the organization".

**Primary recommendation:** New fork module `app/Appearance/` (provider, side tables, 3 routes, web-group Inertia share, Blade boot partial) + `resources/css/untangle-theme.css` (tokens, 7 accent presets, Syne headings) + `resources/js/appearance/` (presets data, `useAppearance`, `AccentPicker`, `OrganizationIconForm`, contrast tests). Core edits are limited to ~9 additive one-liners listed in "Core file touch list".

### Pattern 1: Token override stylesheet (BRAND-01)

**When:** All colour changes. No template edits.
**Wiring:** `resources/css/app.css` gets one line after the existing import: `@import './untangle-theme.css';`. `authorize.blade.php` loads `resources/css/app.css` too (line `@vite('resources/css/app.css')`), so the OAuth page gets the same palette for free. `@solidtime/ui` is a published package whose `styles.css` stays byte-identical to upstream.

### Pattern 2: Accent = class on `<html>`, scale per mode
**What:** `<html class="dark accent-rose">`. Selectors `html:root.<mode>.accent-<id>` (0,4,1) beat the default scale (0,2,1) and the shared sky scale (0,1,0). Light and dark scales differ (see presets) because the shared system uses different steps in each mode (light: 600 button background with white-ish text, 800 foreground on 100, 400/500 for link text and charts; dark: 300 as the working colour, 100 foreground, 200 charts) [VERIFIED: styles.css:51-61 dark, :98-109 light].

### Pattern 3: Fork web routes + web-group Inertia share (precedent: Phase 2/3)
Provider registers the middleware with `$router->pushMiddlewareToGroup('web', ShareAppearanceInertiaData::class);`, routes with `$this->loadRoutesFrom(...)`, migrations with `$this->loadMigrationsFrom(...)` (exactly as `Microsoft365ServiceProvider.php:35-38`). One line in `config/app.php` registers it (`Microsoft365ServiceProvider::class` is at `config/app.php:250`, add the new provider beside it). Inertia data must be shared from a web-group middleware, not `boot()`, because Octane flushes shared props per request (documented in the M365 provider docblock).

```php
// app/Appearance/routes/appearance.php
Route::middleware(['web', 'auth:web', 'auth.session', 'verified'])->group(function (): void {
    // No user id anywhere: always the session user.
    Route::put('/user/appearance', [AppearanceController::class, 'update'])
        ->middleware('throttle:60,1,appearance:')
        ->name('appearance.update');

    Route::post('/organizations/{organization}/icon', [OrganizationIconController::class, 'store'])
        ->whereUuid('organization')->middleware('throttle:20,1,org-icon:')->name('organizations.icon.store');
    Route::delete('/organizations/{organization}/icon', [OrganizationIconController::class, 'destroy'])
        ->whereUuid('organization')->middleware('throttle:20,1,org-icon:')->name('organizations.icon.destroy');
});
```

## Typography (Syne) feasibility

- **Feasible and safe for headings/chrome; not recommended for dense data.** The brand says Syne for display and body, but the app's data surfaces use 10-13px text (`text-2xs` 0.625rem calendar entries, `text-sm` 0.8125rem tables, `text-base` is only 0.9375rem; `tailwind.theme.js` fontSize block), `tabular-nums` figures and Inter's `cv02 cv03 cv04 cv11` features (`app.css`). ## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Contrast ratio math | Own sRGB/luminance code | `chroma-js` `luminance()` (installed; identical to the WCAG relative-luminance formula) + a 10-line `composite()` | One tested formula; already in the bundle graph |
| Theme/accent persistence in the browser | Manual `localStorage` get/set | `useStorage` from `@vueuse/core` (already the `theme` mechanism) | Reactive, cross-tab, existing key `theme` stays compatible |
| Debounced server write | `setTimeout` bookkeeping | `watchDebounced` / `useDebounceFn` from `@vueuse/core` | Already a dependency |
| Image validation & decoding | New MIME sniffing | `Base64ImageRule` + `Base64File::decode/extension` (core, unchanged) | D-06; handles base64 with/without data-URL prefix, finfo MIME sniff, size cap |
| Permission check | `$user->role === 'owner'` | `PermissionStore::has($org, 'organizations:update')` | Single source of truth; handles custom roles and membership |

## Common Pitfalls

### Pitfall 1: Accent applied without a class change
**What goes wrong:** charts (`useCssVariable('--theme-color-chart')`) and calendar entry colours (`useCssVariable('--color-bg-background')`, mixed in `useCalendarEvents.ts:212-215`) stay on the old colour after an accent change.
**Why:** the observer watches only the `class` attribute (`useCssVariable.ts:21,29`).
**How to avoid:** accent switch = `classList` change on `<html>`. Test it: Vitest mounts a component using `useCssVariable`, switches the class, asserts the value updates.

### Pitfall 2: Specificity/order of the override stylesheet
**What goes wrong:** the sky scale (`:root`, 0,1,0) or `:root.dark` tokens win and the brand colours do not apply.
**How to avoid:** `html:root.<mode>` selectors; import after `styles.css`; a Vitest test fails if any `--color-*` override in the fork file uses a selector weaker than `html:root.<mode>`.

### Pitfall 3: `no-preference` is not what you think
D-02 says dark when the OS gives no preference. In current browsers `prefers-color-scheme: light` matches when the user has no preference, so `usePreferredColorScheme` returns `light` and `'no-preference'` is effectively unreachable; `authorize.blade.php` already derives `'dark' : 'light'` only. The boot script keeps the literal rule (dark if neither query matches) so behaviour is identical to `theme.ts`. Practical effect: a user with a light OS sees light by default. If the owner meant "Untangle is dark-first", D-02 needs revisiting (Open Question 3). Do not silently change it.

### Pitfall 4: Pre-existing flash is not caused by this phase but is visible in it
Inertia pages have no pre-paint script today; test the boot partial with a Playwright run that blocks the JS bundle so only the inline script can have applied the classes.

### Pitfall 5: Server wins vs localStorage drift
The boot script writes the server value to localStorage on every full load, but `useStorage` caches the value at module init. Because the module runs after the head script this is consistent; do **not** also call `themeSetting.value = server` on mount (it would trigger a pointless PUT). Guard the persist watcher with a `skipFirst`/`isSeeding` flag.

### Pitfall 6: `Inertia::share` in `boot()`
Octane flushes shared props per request; share from the web-group middleware (precedent comment in `Microsoft365ServiceProvider`/`ShareMicrosoftInertiaData`). Also never keep the memoised appearance row in a static/singleton; use `$request->attributes`.

### Pitfall 7: Route-model binding and non-UUID segments
Add `->whereUuid('organization')`; otherwise `/organizations/not-a-uuid/icon` reaches Postgres and 500s.

### Pitfall 8: Orphaned files
FK cascade removes the `organization_icons` row on organization/user deletion but not the file. Register a listener on the existing `BeforeOrganizationDeletion` event (dispatched by `DeletionService::deleteOrganization`, line 54, also used by the Filament delete action) in the provider with `Event::listen`. Test with `Storage::fake` + `DeletionService`.

### Pitfall 9: Icon cache
Reuse of a stable filename would serve stale images. The uuid-per-upload path avoids it; do not overwrite in place.

### Pitfall 10: `tailwind-merge` and custom colour classes
`TimeTrackerStartStop` uses `cn()`; an unknown `text-on-accent` class may be treated as ambiguous with font-size. Use an arbitrary-value class `text-[color:var(--color-on-accent)]` or add explicit colours per compound variant.

### Pitfall 11: Parallel phase collisions
Phase 3.1 runs in parallel and owns `OutlookGhostLayer.vue`, `TimeEntryCalendar.vue`, `useContextMenu.ts`, `calendarSettings.ts` and several fork files. Phase 3.2 must not edit them. The only shared file is `docs/m365/TOUCHED-CORE-FILES.md`: append 3.2 rows under a **new `## Phase 3.2` heading at the end** to avoid textual merge conflicts, and rebase before pushing. `CalendarDayColumn.vue` hard-codes sky `rgba(14, 165, 233, ...)` in activity boxes (lines 342-418); 3.1's UI-SPEC says it will not touch that file, but those are desktop-activity cosmetics outside BRAND-04: leave as a deferred polish item.

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
